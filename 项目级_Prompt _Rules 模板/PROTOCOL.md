## 一、 Confirmed Requirements (已确认的硬性需求)

> 来源：2026年 INVC 嵌入式软件方向考核题目

### 1. 协议帧结构必备要素
* **REQ-PROTO-01 [核心字段完整性]**：自定义通信帧结构必须包含以下全部要素：
  1. **帧头 (Header)**；
  2. **有效数据长度 (Length)**；
  3. **功能码 (CMD / Function Code)**；
  4. **数据载荷 (Payload)**；
  5. **校验字段 (Check Field，如 CRC 或累加和)**；
  6. **帧尾 (Tail)**。
* **REQ-PROTO-02 [设计论述与答辩]**：必须在设计报告中以独立章节阐述帧结构定义、设计理由及校验算法选择依据；现场答辩必须能清晰陈述协议逻辑（无法清晰阐述者，通信部分最高仅得 50% 分数）。

### 2. 封包、解包与抗干扰机制
* **REQ-PROTO-03 [手柄端封包]**：手柄端必须按照自定义协议将各传感器与控制数据规范打包外发。
* **REQ-PROTO-04 [接收端完整解析]**：接收端必须完整解析数据包，严禁仅进行原始数据透传而不做本地协议解析（无清晰协议或仅原始透传者本项计 0 分）。
* **REQ-PROTO-05 [粘包拆包与丢包处理]**：解包逻辑必须具备完善的**粘包拆包**与**丢包重传 / 超时重发**处理策略。

### 3. 数据统计与可视化要求
* **REQ-PROTO-06 [通信频率统计]**：接收端通过 USB 转 TTL 串口将解析后的有效数据包转发至电脑串口助手，必须统计并打印 **1 秒内接收到的有效数据包数量（即通信频率 Hz）**。
* **REQ-PROTO-07 [实时丢包率呈现]**：接收端 OLED 屏幕必须实时刷新显示从手柄端接收到的数据，同时必须在屏幕上显示本端统计的**实时丢包率（%）**与**通信频率（Hz）**。
* **REQ-PROTO-08 [上位机可视化]**：接收端转发数据至上位机（如串口调试助手或 VOFA+），直观呈现数据变化（推荐仪表盘、动态波形或姿态立方体）。

### 4. 物理层接口与备用链路
* **REQ-PROTO-09 [片上硬件外设与透明透传]**：两端无线通信必须采用片上硬件串口外设（USART1，115200 8N1）。无线模块为**现成的硬件透明串口透传模块**（两端已硬件配对），发送端向 `USART1` 发送的字节流在接收端 `USART1` 直接原样收到，单片机端完全无需编写无线底层驱动或 AT 指令。
* **REQ-PROTO-10 [有线备用直连通道]**：评测期间若因无线干扰或信号问题导致通信速率过低，允许临时改为杜邦线交叉直连两端 MCU 的串口进行辅助验证（TX 接 RX，RX 接 TX，且必须共地）。由于无线模块本身即为纯透明串口通路，软件协议在无线与有线直连之间**完全无缝兼容，无需任何代码改动**。

## 三、 Confirmed Protocol Specification (已正式立项确立的 23 字节通信协议终态规范)

依据系统 Step 8【数据设计】成果与竞赛考核要求，正式立项确定全系统统一采用 **23 字节定长二进制强类型通信帧**：

### 1. 终态帧结构字节排布定义 (23 Bytes)
```text
┌───────┬───────┬────────┬────────┬───────┬──────────────────────┬──────────┬──────┐
│ Byte0 │ Byte1 │ Byte2  │ Byte3  │ Byte4 │ Byte 5 ~ Byte 20     │ Byte 21  │Byte22│
├───────┼───────┼────────┼────────┼───────┼──────────────────────┼──────────┼──────┤
│ 0xAA  │ 0x55  │ Seq_ID │ Length │  CMD  │ 16-Byte Payload      │ Checksum │ 0x0D │
│ 帧头1 │ 帧头2 │ 序列号 │ 定长16 │  0x01 │ 遥测物理量数据载荷   │ 累加和   │ 帧尾 │
└───────┴───────┴────────┴────────┴───────┴──────────────────────┴──────────┴──────┘
```

### 2. 16 字节载荷内部数据排布规范 (Little-Endian, Pack=1)
| 载荷偏移 | 字段名 | 类型 | 取值范围 | 分辨率与量纲 | 物理含义 |
|---|---|---|---|---|---|
| +0 ~ +1 | `joy_x_raw` | `int16_t` | -1000 ~ +1000 | 1 | 摇杆 X 轴归一化值（小端序） |
| +2 ~ +3 | `joy_y_raw` | `int16_t` | -1000 ~ +1000 | 1 | 摇杆 Y 轴归一化值（小端序） |
| +4 ~ +5 | `joy_x_mv` | `uint16_t` | 0 ~ 3300 | 1 mV | 摇杆 X 物理采样电压（小端序） |
| +6 ~ +7 | `joy_y_mv` | `uint16_t` | 0 ~ 3300 | 1 mV | 摇杆 Y 物理采样电压（小端序） |
| +8 | `key_mask` | `uint8_t` | 0x00 ~ 0x0F | 位掩码 | 4路按键（Bit0~3: KEY1~KEY4，1=按下） |
| +9 | `switch_mask`| `uint8_t` | 0x00 ~ 0x03 | 位掩码 | 2位拨码（Bit0~1: SW1~SW2，1=高电平） |
| +10 ~ +11| `pitch_cd` | `int16_t` | -1800 ~ +1800 | 0.1° (厘度) | 俯仰角，$-180.0^\circ \sim +180.0^\circ$ |
| +12 ~ +13| `roll_cd` | `int16_t` | -1800 ~ +1800 | 0.1° (厘度) | 横滚角，$-180.0^\circ \sim +180.0^\circ$ |
| +14 ~ +15| `yaw_cd` | `int16_t` | 0 ~ 3600 | 0.1° (厘度) | 航向角，$0.0^\circ \sim 360.0^\circ$ |

### 3. 校验算法与数学公式
* **算法**：8-bit 无符号累加和。
* **计算区间**：从 Byte 2 (`Seq_ID`) 开始累加至 Byte 20 (`yaw_cd` 高字节)，共计 19 字节：
  $$\text{Checksum} = \left( \text{Seq\_ID} + \text{Length} + \text{CMD} + \sum_{i=0}^{15} \text{Payload}[i] \right) \pmod{256}$$

## 四、 Resolved Technical Items & Closed Decisions (已决策闭环事项)

1. **协议格式决策 [已确立]**：正式确立为 23 字节定长二进制帧（16 字节载荷），全系统小端序，内存 1 字节紧凑对齐（`#pragma pack(push, 1)`）。
2. **校验算法决策 [已确立]**：采用 8-bit 无符号累加和校验。算力开销小，适合 72MHz Cortex-M3 高频流式解析。
3. **通信信道与传输策略 [已确立]**：
   * 采用“**高频单向广播流 (20Hz~50Hz) + 接收端序列号环形丢包统计**”策略；
   * 坚决避免在半双工无线空口频繁回传 ACK 导致的电磁波碰撞与信道拥堵；
   * 具备有线杜邦线交叉直连（TX-RX, RX-TX, GND）100% 无缝热切换测试支持。
4. **功能码定义 [已确立]**：
   * `0x01`：综合遥测数据帧（手柄 $\rightarrow$ 接收端，高频下发）；
   * `0x02`：心跳/连接状态帧（预留）；
   * `0x03`：传感器现场校准指令（预留）。
5. **PC 上位机转发格式 [已确立]**：
   * 接收端 USART2 既支持透传转发原始 16 字节载荷供上位机解析，亦支持格式化为 VOFA+ JustFloat 协议输出动态波形与 3D 姿态。

## 五、 Protocol Compatibility Rules (协议一致性守则)

1. 通信协议已在 `sender/Service/srv_protocol.h` 与 `receiver/Service/srv_protocol.h` 中落地，**发送端、接收端与 PC 上位机解析三端必须保持 100% 同步**。
2. 任何协议字段增减或缩放系数修改，必须经过评审并同步更新系统规范与三端工程。
