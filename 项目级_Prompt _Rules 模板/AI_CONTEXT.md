## 1. Project Overview (项目概述)

* **项目名称**：无线串口手柄系统 (Wireless Serial Controller System)
* **项目目标**：基于两套 STM32F103C8T6 核心板，在**纯面包板手工插接**搭建环境下，实现手柄发送端（Sender）与接收端（Receiver）之间通过无线串口透传模块进行数据采集、传输、解析、本地显示与上位机可视化呈现。
* **使用场景**：模拟多通道遥控器（如无人机/智能小车遥控）、传感器状态采集上报、多级菜单交互、数据通信质量（丢包率/频率）监测。
* **系统总体功能**：
  * **手柄发送端**：采集双轴摇杆模拟量（ADC+DMA）、扫描 4 个独立按键（按下/释放/长按/双击）与 2 位拨码开关稳态，通过硬件 SPI 接口读取六轴 IMU 原始数据并解算姿态角（Pitch/Roll/Yaw），在 0.96 寸 I2C OLED 上通过多级菜单呈现数据，按自定义协议打包外发至无线串口，并通过独立调试串口向电脑打印采集日志。
  * **接收端**：通过无线串口接收并解析手柄发送的数据包，统计 1 秒窗口内的有效通信频率（Hz）与实时丢包率（%），通过 0.96 寸 I2C OLED 显示接收到的遥测值及统计指标，同时通过 USB 转 TTL 串口将数据转发至电脑上位机进行可视化显示。

* **【绝不允许使用 PCB】**：全部硬件必须在面包板上手工插接完成，**严禁使用任何自制或商用成品 PCB**，违者不予评测。
* **【必须使用硬件外设通信】**：所有通信方式（I2C、SPI、UART）**必须全部采用 STM32 片上硬件外设**，**严禁使用软件模拟 IIC、软件模拟 SPI 或软件模拟串口**。
* **【IMU 芯片接口与解算红线】**：IMU **必须采购并使用 SPI 接口版本**；**严禁使用自带 DMP 或出厂已解算完毕的智能姿态传感器**，必须在本地通过软件算法解算滤波。

* **【供电安全红线】**：电池必须选用**带保护板**的锂电池组，电压范围 $\le 12.6\text{V}$，降压后供电。严禁使用无保护板软包聚合物电池。
* **【现场测试禁止烧录】**：正式评测期间**严禁连接烧录器（ST-Link/J-Link）**修改代码或重新烧录，仅能通过物理按键复位或重新插拔电源。
* **【双串口联合验证】**：测试时手柄调试串口与接收端转发串口必须同时接入电脑打印，缺少任一端信息将扣分。严禁两端仅使用无线透传而不进行本地处理。
* **【OLED 单静态页计 0 分】**：手柄端 OLED 必须具备按键交互的多级菜单，单一静态展示页直接计 0 分。

## 3. System Architecture (系统总体链路架构)

依据考核要求，系统总体数据链路与功能走向如下：

```text
[双轴摇杆] ───► ADC1+DMA ──┐
[4×轻触按键] ──► GPIO ─────┤
[2×拨码开关] ──► GPIO ─────┼──► [手柄端 STM32] ──► [0.96" OLED] (I2C1 多级菜单)
[六轴 IMU] ───► SPI1 ──────┘          │
                                      ▼ (协议封包)
                             [无线串口透传模块] (USART1)
                                      │
                                (无线空口 / 交叉杜邦线)
                                      │
                                      ▼
                             [无线串口透传模块] (USART1)
                                      │
                                      ▼ (协议流式解包 + 丢包率/频率统计)
                               [接收端 STM32] ──► [0.96" OLED] (I2C1 实时显示)
                                      │
                                      ▼ (USART2 数据转发)
                               [PC 电脑端上位机] (VOFA+ / 串口助手可视化)

* 注：评测时手柄端通过独立 USART2 输出本地调试日志，两端同时接受电脑监视。
```

## 4. Hardware (硬件配置与器件信息)

### 4.1 手柄发送端 (Transmitter)
* **MCU**：STM32F103C8T6 最小系统板（LQFP48，64KB Flash，20KB SRAM，主频 72MHz，外部 8MHz HSE 晶振）。
* **摇杆模块**：双轴模拟摇杆，输出 X/Y 模拟电压（0 ~ 3.3V）。
* **按键与开关**：4 个轻触按键（内部上拉输入）；2 位拨码开关（内部上拉输入）。
* **IMU 传感器 (已确认)**：InvenSense **MPU6500** 六轴惯性传感器（SPI 通信版本），引脚规划 `PA4 (MPU_CS)` 片选，`PA5/PA6/PA7 (SPI1)` 通信。参考接入驱动位于 `驱动_框架/mpu6500_driver/mpu6500`（LibDriver 工业级驱动，采用 basic 模式读取原始加速度与角速度，**严禁使用 DMP**，姿态解算必须由 MCU 本地软件滤波算法完成）。
* **OLED 屏幕 (已确认)**：0.96 寸 128×64 单色 OLED 屏幕（芯片已确认统一为 **SSD1306**，硬件 I2C 接口，`PB6 (I2C1_SCL)`，`PB7 (I2C1_SDA)`，从机地址 0x78）。参考底层例程位于 `驱动_框架/OLED_display/底层驱动源码/STM32例程/01-0.96OLED显示屏STM32F103C8T6_IIC例程/`，多级菜单框架参考位于 `驱动_框架/OLED_display/MiaoUI/`。
* **无线串口透传模块 (现成硬件透明通道)**：已采购配对好的现成硬件串口透传模块，**纯透明数据传输**。发送端 MCU 将数据写入片上硬件 `USART1`，对端接收模块自动空中接收并直接由接收端 MCU 的 `USART1_RX` 接收。单片机端**完全无需编写无线底层驱动、无需发送 AT 指令、无需处理射频配对**，在软件开发中完全等同于直接物理串口通信。
* **本地调试串口**：USB 转 TTL 模块，连接 USART2。
* **供电单元**：带保护板锂电池组（$\le 12.6\text{V}$）+ 降压稳压模块。

### 4.2 接收端 (Receiver)
* **MCU**：STM32F103C8T6 最小系统板（与手柄端相同）。
* **无线串口透传模块 (现成硬件透明通道)**：与手柄端配对的现成硬件透传模块，直接从片上 `USART1` 接收来自手柄的原始字节流。
* **OLED 屏幕 (已确认)**：0.96 寸 128×64 单色 OLED 屏幕（SSD1306，硬件 I2C 接口，`PB6 (I2C1_SCL)`，`PB7 (I2C1_SDA)`）。
* **上位机转发接口**：USB 转 TTL 模块，连接 USART2 向上位机转发数据。
* **供电单元**：带保护板锂电池组 + 降压模块，或 PC USB 供电。

### 4.3 第三方参考驱动与开源框架资源库 (驱动_框架/ 资产清单)

项目根目录 `驱动_框架/` 已入库关键外设的参考驱动与 UI 框架，供后续驱动移植与应用开发参考：

#### 4.3.1 LibDriver MPU6500 六轴惯性传感器驱动库 (`驱动_框架/mpu6500_driver/mpu6500/`)
* **框架定位**：LibDriver 开源生态维护的工业级、跨平台、符合 MISRA C 规范的 MPU6500 完整驱动。
* **硬件接口对接**：
  - 硬件总线：片上硬件 SPI1（PA5-SCK, PA6-MISO, PA7-MOSI），Motorola 模式 0（CPOL=0, CPHA=0），9MBits/s。
  - 片选引脚：PA4 (`MPU_CS`)，推挽输出，默认高电平拉高。
  - 移植对接点：通过实现 `interface/driver_mpu6500_interface.c` 中的 SPI 发送/接收、毫秒延时、调试输出函数指针，与 STM32 HAL 库无缝衔接，隔离底层硬件细节。
* **工作模式选择**：采用 `example/driver_mpu6500_basic.c`，以轮询/非阻塞方式读取原始 3 轴加速度计与 3 轴陀螺仪 16 位补码数据。
* **【绝不可逾越的竞赛合规红线】**：
  - 竞赛规则明确禁止使用具备硬件姿态解算/DMP 输出的现成模块。
  - **本项目严禁调用 LibDriver 的 `driver_mpu6500_dmp.c/.h` 或载入 DMP 固件！**
  - MPU6500 仅用于采集原始传感器数据，姿态角（Pitch、Roll、Yaw）必须在 STM32 本地由软件服务层 (`srv_imu_filter`) 算法解算。

#### 4.3.2 0.96 寸 OLED 底层参考例程 (`驱动_框架/OLED_display/底层驱动源码/.../01-0.96OLED显示屏STM32F103C8T6_IIC例程/`)
* **框架定位**：标准 SSD1306 0.96 寸 128×64 OLED 屏幕官方 C8T6 移植例程。
* **核心复用资产**：
  - SSD1306 经典初始化寄存器配置时序（Charge Pump、寻址模式、对比度控制、显示偏移等）。
  - 点阵字库文件（`oledfont.h`），包含常用 6×8 和 8×16 ASCII 字符点阵。
  - 1024 字节全屏点阵显存管理（128×64 / 8 字节）机制与页面刷新指令。
* **硬件总线适配注意**：
  - 参考例程源码为软件模拟 I2C（基于 GPIOA 翻转）。
  - **本项目硬件已由 CubeMX 严格配置为硬件 I2C1 外设 (PB6/PB7，400kHz Fast Mode)**。
  - 移植时必须将底层的 `OLED_WR_Byte()` 改造为调用硬件 `HAL_I2C_Mem_Write()`，严禁降级为软件模拟 I2C。

#### 4.3.3 MiaoUI 多级 OLED 菜单框架 (`驱动_框架/OLED_display/MiaoUI/`)
* **框架定位**：专为单色 OLED 设计的高颜值、现代轻量级 C 语言多级菜单 UI 框架。
* **核心功能特性**：
  - 采用双向链表灵活组织多级页面与列表/图标菜单项。
  - 内置流畅的 Q 弹非线性动画与超长文本跑马灯自动滚动。
  - 原生支持 float、int、bool 实时参数调定与单选框控件。
  - 具备良好的输入设备解耦（`indevDriver`）与显示设备解耦（`dispDriver`）。
* **资源裁剪与裸机适配准则**：
  - MiaoUI 源码工程中附带了 FreeRTOS、FatFS、MultiButton 等第三方库。
  - **本项目为裸机状态机架构，严禁引入 FreeRTOS 或文件系统**。
  - 仅复用 MiaoUI 核心 UI 调度器（`core/`）、基础控件（`widget/`）与精简字体，将其驱动层直接对接本项目的 `bsp_key`（按键事件输入）和 `bsp_oled`（屏幕显存刷新），控制 Flash 占用在 10~15KB 左右。

## 6. Software Architecture (软件架构)

### 6.1 当前实际架构 (Current Architecture)
当前工程为纯 CubeMX 初始状态：
* 两端工程结构为 MDK-ARM Keil 5 项目。
* 目录仅包含 ST 官方驱动 `Drivers/` 以及自动生成的配置代码 `Core/Src` 与 `Core/Inc`。
* 外设初始化已分对生成为 `gpio.c/.h`、`adc.c/.h`、`dma.c/.h`、`i2c.c/.h`、`spi.c/.h`、`usart.c/.h`。
* `main.c` 仅包含硬件外设初始化函数调用及空的 `while(1)` 死循环。
* **代码库中目前尚未编写任何业务逻辑代码、外设驱动代码或算法代码**。

### 6.2 软件架构与模块划分设计状态 (Design Status)
* **状态标记**：**已完成软件架构设计与模块划分 (已落盘至 MODULE_ARCHITECTURE.md)**。
* **架构核心理念**：
  * **四层分层架构**：`Layer 4 应用层 (Application)` $\rightarrow$ `Layer 3 核心服务层 (Service/Middleware)` $\rightarrow$ `Layer 2 板级硬件抽象层 (BSP/Driver)` $\rightarrow$ `Layer 1 芯片硬件层 (MCU/HAL)`；
  * **高可移植性保障**：Service 层（协议组帧、流式解包、姿态滤波、环形缓冲、1s统计）为纯 ANSI C 实现，严禁依赖底层 HAL 库，未来更换 F4/H7/其他 MCU 业务代码无感复用；
  * **单向依赖规则**：上层可调用下层，下层严禁反向 include 上层头文件，严禁跳层破坏封装；
  * **执行原则**：当前阶段仅在系统提示词模板中确立架构设计规范与模块职责，**未在工程中提前创建源文件或编写代码**。

## 7. Runtime Architecture (运行时架构)

### 7.1 当前底层硬件事实 (Current Hardware Facts)
* **时钟节拍**：两端 MCU 均由 SysTick 提供 1ms 系统时钟基准（`HAL_GetTick()`）。
* **ADC 采样**：手柄端 ADC1 结合 DMA1_Channel1 循环搬运，硬件底层自动在内存缓冲区更新转换数值，无需占用 CPU 中断。
* **串口通信中断**：两端工程在 CubeMX 中均已使能 `USART1_IRQHandler`，手柄端使能了 `USART2_IRQHandler`。

### 7.2 运行时行为与状态机设计状态 (Design Status)

## 9. Important Constraints (核心项目硬约束)

1. **不可破坏 CubeMX 代码保护区**：所有后续用户代码只能书写在 `/* USER CODE BEGIN xxx */` 与 `/* USER CODE END xxx */` 注释区间之内或独立新增的文件中。
2. **栈空间预算约束**：两端工程栈空间配置为 `0x800` (2048 字节)。OLED 屏幕显存为 1024 字节，**绝对严禁将 1KB 显存缓冲区定义为函数局部变量**（会导致栈溢出 HardFault），必须使用静态全局存储。
3. **禁止动态内存分配**：严禁在循环和业务逻辑中使用 `malloc()` / `free()`。
4. **中断响应时间约束**：USART 中断服务程序必须极简，严禁在中断上下文中执行耗时运算、阻塞等待、I2C 屏幕刷新或 printf。
5. **无硬件浮点运算开销**：STM32F103 无硬件 FPU，所有浮点运算均为软件仿真，高频算法中应注意浮点开销控制。

1. **IMU 芯片具体型号 (已确认)**：已正式确定为 **InvenSense MPU6500**（片上 SPI1 通信，参考驱动已入库至 `驱动_框架/mpu6500_driver/mpu6500`，执行 basic 模式原始数据采集，严禁使用片上 DMP）。
2. **OLED 驱动芯片型号 (已确认)**：已正式确定为 **SSD1306**（0.96 寸 128×64 单色屏，硬件 I2C1 PB6/PB7，底层例程参考 `01-0.96OLED例程`，多级菜单框架参考 `MiaoUI`）。
3. **无线透传模块特性 (已确认)**：已明确为**现成硬件纯透明串口透传模块**，发送端串口发出数据即在接收端串口直接收到，单片机端完全无需编写无线/AT指令驱动，等同于硬件串口电缆。
4. **通信可靠性策略 (已确认)**：基于 `PROTOCOL.md` 与 `EXCEPTION_BOUNDARY.md`，确立 50Hz (20ms) 周期性流控单向遥测推送；接收端实行 1000ms 超时离线判定与环形模 256 丢包统计，避免半双工信道频繁回发引发电磁波空中碰撞。
5. **校验算法选型 (已确认)**：采用 Byte 2 ~ Byte 20 的 8 位累加和校验（Sum Check），兼顾 72MHz 单片机极简运算开销与空中噪声检错能力。
6. **摇杆通道数量确认 (已确认)**：CubeMX 已配置 1 个双轴摇杆所需的 2 个 ADC 通道（ADC1_IN0/PA0 为 X 轴，ADC1_IN1/PA1 为 Y 轴），配合 DMA 循环搬运。
