## 1. Project Overview (项目概述)

* **项目名称**：无线串口手柄系统 (Wireless Serial Controller System)
* **项目目标**：基于两套 STM32F103C8T6 核心板，在**纯面包板手工插接**搭建环境下，实现手柄发送端（Sender）与接收端（Receiver）之间通过无线串口透传模块进行数据采集、传输、解析、本地显示与上位机可视化呈现。
* **使用场景**：模拟多通道遥控器（如无人机/智能小车遥控）、传感器状态采集上报、多级菜单交互、数据通信质量（丢包率/频率）监测。
* **系统总体功能**：
  * **手柄发送端**：采集双轴摇杆模拟量（ADC+DMA）、扫描 4 个独立按键（按下/释放/长按/双击）与 2 位拨码开关稳态，通过硬件 SPI 接口读取六轴 IMU 原始数据并解算姿态角（Pitch/Roll/Yaw），在 0.96 寸 I2C OLED 上通过多级菜单呈现数据，按自定义协议打包外发至无线串口，并通过独立调试串口向电脑打印采集日志。
  * **接收端**：通过无线串口接收并解析手柄发送的数据包，统计 1 秒窗口内的有效通信频率（Hz）与实时丢包率（%），通过 0.96 寸 I2C OLED 显示接收到的遥测值及统计指标，同时通过 USB 转 TTL 串口将数据转发至电脑上位机进行可视化显示。

* **【绝不允许使用 PCB】**：全部硬件必须在面包板上手工插接完成，**严禁使用任何自制或商用成品 PCB**，违者不予评测。
* **【必须使用硬件外设通信】**：所有通信方式（I2C、SPI、UART）**必须全部采用 STM32 片上硬件外设**，**严禁使用软件模拟 IIC、软件模拟 SPI 或软件模拟串口**。

* **【供电安全红线】**：电池必须选用**带保护板**的锂电池组，电压范围 $\le 12.6\text{V}$，降压后供电。严禁使用无保护板软包聚合物电池。
* **【现场测试禁止烧录】**：正式评测期间**严禁连接烧录器（ST-Link/J-Link）**修改代码或重新烧录，仅能通过物理按键复位或重新插拔电源。
* **【双串口联合验证】**：测试时手柄调试串口与接收端转发串口必须同时接入电脑打印，缺少任一端信息将扣分。严禁两端仅使用无线透传而不进行本地处理。
* **【OLED 单静态页计 0 分】**：手柄端 OLED 必须具备按键交互的多级菜单，单一静态展示页直接计 0 分。

## 3. System Architecture (系统总体链路架构)

依据考核要求，系统总体数据链路与功能走向如下：

```text
[双轴摇杆] ───► ADC1+DMA ──┐
[4×轻触按键] ──► GPIO ─────┤
[2×拨码开关] ──► GPIO ─────┼──► [手柄端 STM32] ──► [0.96" OLED] (I2C1 多级菜单)
[六轴 IMU] ───► SPI1 ──────┘          │
                                      ▼ (协议封包)
                             [无线串口透传模块] (USART1)
                                      │
                                (无线空口 / 交叉杜邦线)
                                      │
                                      ▼
                             [无线串口透传模块] (USART1)
                                      │
                                      ▼ (协议流式解包 + 丢包率/频率统计)
                               [接收端 STM32] ──► [0.96" OLED] (I2C1 实时显示)
                                      │
                                      ▼ (USART2 数据转发)
                               [PC 电脑端上位机] (VOFA+ / 串口助手可视化)

* 注：评测时手柄端通过独立 USART2 输出本地调试日志，两端同时接受电脑监视。
```

## 4. Hardware (硬件配置与器件信息)

### 4.1 手柄发送端 (Transmitter)
* **MCU**：STM32F103C8T6 最小系统板（LQFP48，64KB Flash，20KB SRAM，主频 72MHz，外部 8MHz HSE 晶振）。
* **摇杆模块**：双轴模拟摇杆，输出 X/Y 模拟电压（0 ~ 3.3V）。
* **按键与开关**：4 个轻触按键（内部上拉输入）；2 位拨码开关（内部上拉输入）。
* **IMU 传感器**：六轴传感器（SPI 通信版本），引脚规划 `MPU_CS`（芯片具体型号待采购实物确定，标记为 `TBD`）。
* **OLED 屏幕**：0.96 寸 128×64 单色 OLED 屏幕（硬件 I2C 接口，芯片通常为 SSD1306）。
* **无线透传模块**：无线串口透传模块（型号待定，波特率配置为 115200 8N1）。
* **本地调试串口**：USB 转 TTL 模块，连接 USART2。
* **供电单元**：带保护板锂电池组（$\le 12.6\text{V}$）+ 降压稳压模块。

### 4.2 接收端 (Receiver)
* **MCU**：STM32F103C8T6 最小系统板（与手柄端相同）。
* **无线透传模块**：无线串口透传模块（与手柄端配对）。
* **OLED 屏幕**：0.96 寸 128×64 单色 OLED 屏幕（硬件 I2C 接口）。
* **上位机转发接口**：USB 转 TTL 模块，连接 USART2 向上位机转发数据。
* **供电单元**：带保护板锂电池组 + 降压模块，或 PC USB 供电。

## 6. Software Architecture (软件架构)

### 6.1 当前实际架构 (Current Architecture)
当前工程为纯 CubeMX 初始状态：
* 两端工程结构为 MDK-ARM Keil 5 项目。
* 目录仅包含 ST 官方驱动 `Drivers/` 以及自动生成的配置代码 `Core/Src` 与 `Core/Inc`。
* 外设初始化已分对生成为 `gpio.c/.h`、`adc.c/.h`、`dma.c/.h`、`i2c.c/.h`、`spi.c/.h`、`usart.c/.h`。
* `main.c` 仅包含硬件外设初始化函数调用及空的 `while(1)` 死循环。
* **代码库中目前尚未编写任何业务逻辑代码、外设驱动代码或算法代码**。

### 6.2 软件架构与模块划分设计状态 (Design Status)
* **状态标记**：**已完成软件架构设计与模块划分 (已落盘至 MODULE_ARCHITECTURE.md)**。
* **架构核心理念**：
  * **四层分层架构**：`Layer 4 应用层 (Application)` $\rightarrow$ `Layer 3 核心服务层 (Service/Middleware)` $\rightarrow$ `Layer 2 板级硬件抽象层 (BSP/Driver)` $\rightarrow$ `Layer 1 芯片硬件层 (MCU/HAL)`；
  * **高可移植性保障**：Service 层（协议组帧、流式解包、姿态滤波、环形缓冲、1s统计）为纯 ANSI C 实现，严禁依赖底层 HAL 库，未来更换 F4/H7/其他 MCU 业务代码无感复用；
  * **单向依赖规则**：上层可调用下层，下层严禁反向 include 上层头文件，严禁跳层破坏封装；
  * **执行原则**：当前阶段仅在系统提示词模板中确立架构设计规范与模块职责，**未在工程中提前创建源文件或编写代码**。

## 7. Runtime Architecture (运行时架构)

### 7.1 当前底层硬件事实 (Current Hardware Facts)
* **时钟节拍**：两端 MCU 均由 SysTick 提供 1ms 系统时钟基准（`HAL_GetTick()`）。
* **ADC 采样**：手柄端 ADC1 结合 DMA1_Channel1 循环搬运，硬件底层自动在内存缓冲区更新转换数值，无需占用 CPU 中断。
* **串口通信中断**：两端工程在 CubeMX 中均已使能 `USART1_IRQHandler`，手柄端使能了 `USART2_IRQHandler`。

### 7.2 运行时行为与状态机设计状态 (Design Status)
* **状态标记**：**已完成系统行为与状态机设计 (已落盘至 SYSTEM_BEHAVIOR.md)**。
* **已确立系统行为**：
  * **手柄端行为**：系统生命周期模式（上电/自检校准/正常/故障降级）、按键四事件精准识别状态机（单击/释放/长按2s/双击300ms）、OLED 4大核心页面环形切换状态机、遥测数据非阻塞外发流水线；
  * **接收端行为**：单字节驱动流式解包有限状态机（抗粘包/拆包/抗噪声）、1 秒滑动窗口帧率与丢包率统计流水线、通信中断超时判定与上位机即收即转流水线；
  * **系统级协同行为**：备用交叉杜邦线热切换自适应、I2C/SPI 总线超时防死锁恢复机制。

## 9. Important Constraints (核心项目硬约束)

1. **不可破坏 CubeMX 代码保护区**：所有后续用户代码只能书写在 `/* USER CODE BEGIN xxx */` 与 `/* USER CODE END xxx */` 注释区间之内或独立新增的文件中。
2. **栈空间预算约束**：两端工程栈空间配置为 `0x800` (2048 字节)。OLED 屏幕显存为 1024 字节，**绝对严禁将 1KB 显存缓冲区定义为函数局部变量**（会导致栈溢出 HardFault），必须使用静态全局存储。
3. **禁止动态内存分配**：严禁在循环和业务逻辑中使用 `malloc()` / `free()`。
4. **中断响应时间约束**：USART 中断服务程序必须极简，严禁在中断上下文中执行耗时运算、阻塞等待、I2C 屏幕刷新或 printf。
5. **无硬件浮点运算开销**：STM32F103 无硬件 FPU，所有浮点运算均为软件仿真，高频算法中应注意浮点开销控制。

5. **校验算法选型 (TBD)**：8-bit 累加和还是 CRC16 待定。
6. **摇杆通道数量确认 (TBD)**：原题推荐物料为 2 个双轴摇杆，当前 CubeMX 仅配置了 1 个摇杆所需的 2 个 ADC 通道（PA0/PA1），需确认实物采用 1 个还是 2 个摇杆。
