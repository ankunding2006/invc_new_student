## 第一部分：手柄发送端系统行为设计 (Transmitter Behavior)

### 1.1 手柄系统生命周期与工作模式 (Lifecycle & Operational Modes)

手柄发送端软件生命周期划分为以下 4 种系统级工作状态：

```text
               ┌───────────────────────┐
               │   POWER_ON / RESET    │ (上电复位)
               └──────────┬────────────┘
                          │ 硬件外设初始化完成
                          ▼
               ┌───────────────────────┐
               │ INIT_AND_CALIBRATION  │ (传感器自检与静态校准)
               └──────────┬────────────┘
                          │
         ┌────────────────┴────────────────┐
         │ 校准完成                        │ 传感器严重故障/总线失联
         ▼                                 ▼
┌─────────────────────────┐       ┌─────────────────────────┐
│     NORMAL_RUNNING      │       │     FAULT_DEGRADED      │
│  (正常并发多任务运行态) │       │   (故障降级安全运行态)  │
└────────────┬────────────┘       └────────────┬────────────┘
             │                                 │
             └────────────────►◄───────────────┘
```

#### 模式行为定义：
1. **POWER_ON / RESET (上电复位模式)**：
   - 执行基础硬件初始化（RCC 72MHz 时钟树锁定、GPIO 端口使能、NVIC 中断向量优先级配置、ADC1 DMA 循环通道、SPI1 主机、I2C1 Fast Mode、USART1/2 串口波特率配置）；
   - 初始化系统 1ms 时间戳基准。
2. **INIT_AND_CALIBRATION (自检与零偏校准模式)**：
   - OLED 屏幕初始化，绘制开机 Logo 并提示 `"Calibrating IMU..."`；
   - 自动启动 ADC1 DMA 循环采样，读取机械静态中位电压；
   - 尝试通过 SPI1 读取六轴 IMU 设备 ID（WHO_AM_I）：
     - 若读取成功，保持手柄静止 $1.0\text{s} \sim 2.0\text{s}$，连续采集 100~200 组陀螺仪角速度数据计算均值，作为静态零偏偏置（Gyro Offset）扣除基准；校准通过后转入 `NORMAL_RUNNING`；
     - 若读取连续超时或总线无应答，屏幕提示 `"IMU Init Failed"`，转入 `FAULT_DEGRADED` 降级模式。
3. **NORMAL_RUNNING (正常并发运行模式)**：
   - 并发驱动三大业务状态机与外发工作流：
     - 按键消抖与四事件识别状态机；
     - OLED 多级菜单交互状态机；
     - 传感器采集解算与协议周期封包外发工作流；
     - 串口调试日志打印。
4. **FAULT_DEGRADED (故障降级模式)**：
   - 当检测到 SPI IMU 或 I2C OLED 总线故障时，系统保持非阻塞容错运行，禁止单片机死锁；
   - 姿态角赋默认安全零值（Pitch=0.0°, Roll=0.0°, Yaw=0.0°），并在通信包中置位故障诊断标志；摇杆与按键控制指令正常打包发送，保障核心遥控功能可用；
   - 状态栏闪烁显示 `"IMU ERR"` 告警；后台以 1.0Hz 低频尝试重新探测握手，插好后自动无缝恢复回 `NORMAL_RUNNING`（详见 `EXCEPTION_BOUNDARY.md` 第 2.2 节）。

### 1.2 手柄核心状态机 1：按键多事件精准识别有限状态机 (Key Event FSM)

针对 KEY1 ~ KEY4 共 4 个独立轻触按键，每个按键维护独立的非阻塞有限状态机实例。

```text
               ┌───────────────────────┐
               │    KEY_STATE_IDLE     │◄───────────────────────┐
               └──────────┬────────────┘                        │
                          │ 检测到有效低电平                    │
                          ▼                                     │
               ┌───────────────────────┐                        │
               │  KEY_STATE_DEBOUNCE   │─────────► 抖动消失复位 ┤
               └──────────┬────────────┘ (恢复高电平)           │
                          │ 持续低电平达到消抖门限 (>=20ms)     │
                          ▼                                     │
               ┌───────────────────────┐                        │
       ┌───────┤   KEY_STATE_PRESSED   │                        │
       │       └──────────┬────────────┘                        │
       │                  │                                     │
       │ 按压时间 >= 2.0s │ 按压未满 2.0s 抬起 (电平变高)       │
       │ 立即触发长按事件 │ 触发释放事件                        │
       ▼                  ▼                                     │
┌──────────────┐ ┌───────────────────────┐                      │
│KEY_LONG_PRESS│ │ KEY_STATE_WAIT_DOUBLE │                      │
└──────┬───────┘ └──────────┬────────────┘                      │
       │                    │                                   │
       │ 抬起松手           │ 超过 300ms 窗口未检测到再次按下   │
       │ (不触发单击释放)   │ 判定为普通单击 (发出 EVENT_CLICK) │
       │                    ▼                                   │
       └───────────────────►┴───────────────────────────────────┘
```

#### 状态转换与动作语义量化表：

| 当前状态 (Current State) | 触发条件 (Trigger Condition) | 下一状态 (Next State) | 执行动作与对外事件 (Action & Event) |
|---|---|---|---|
| **KEY_STATE_IDLE** | 引脚检测到低电平 ($V \le 0.8\text{V}$) | `KEY_STATE_DEBOUNCE` | 记录起始时间戳 $t_{\text{start}}$，启动消抖计时。 |
| **KEY_STATE_DEBOUNCE** | 持续低电平时间 $t - t_{\text{start}} \ge 20\text{ms}$ | `KEY_STATE_PRESSED` | 确认物理按下，生成 **`EVENT_PRESS` (按下事件)**，记录按下时间戳 $t_{\text{press}}$。 |
| **KEY_STATE_DEBOUNCE** | 在 20ms 内引脚恢复高电平 | `KEY_STATE_IDLE` | 判定为干扰毛刺，丢弃，无事件产生。 |
| **KEY_STATE_PRESSED** | 保持低电平时间 $t - t_{\text{press}} \ge 2000\text{ms}$ | `KEY_STATE_LONG_PRESS` | **达到 2.0 秒瞬时触发**，生成 **`EVENT_LONG_PRESS` (长按事件)**，标记长按已触发。 |
| **KEY_STATE_PRESSED** | 按压未满 2.0s 时检测到抬起（高电平） | `KEY_STATE_WAIT_DOUBLE` | 生成 **`EVENT_RELEASE` (释放事件)**，记录抬起时间戳 $t_{\text{release}}$，启动双击侦测。 |
| **KEY_STATE_WAIT_DOUBLE**| 在 $t - t_{\text{release}} \le 300\text{ms}$ 内再次检测到有效低电平（经消抖确认） | `KEY_STATE_PRESSED` | 生成 **`EVENT_DOUBLE_CLICK` (双击事件)**，重置按下计时，消除之前的单击判定。 |
| **KEY_STATE_WAIT_DOUBLE**| 抬起后等待超时 $t - t_{\text{release}} > 300\text{ms}$ | `KEY_STATE_IDLE` | 双击窗口关闭，生成 **`EVENT_CLICK` (标准单击事件)**，归位回空闲。 |
| **KEY_STATE_LONG_PRESS** | 引脚检测到抬起（高电平，经消抖） | `KEY_STATE_IDLE` | 长按松开，生成 `EVENT_RELEASE`，**绝对不触发后续单击事件**，直接归位回空闲。 |

```text
         ┌────────────────────────────────────────────────────────┐

         ▼ (KEY1/UP)                                              │ (KEY2/DOWN)

└────────┬────────┘   KEY1 (UP)     └────────┬────────┘           │
         │                                   │                    │
         │ (KEY4: 返回主页)                  │ KEY2 (DOWN)        │
         │                                   ▼                    │
         │                          ┌─────────────────┐           │
         │                          │  PAGE_ATTITUDE  │           │
         │                          │  (IMU姿态监控页)│           │
         │                          └────────┬────────┘           │
         │                                   │                    │
         │                                   │ KEY2 (DOWN)        │
         │                                   ▼                    │
         │                          ┌─────────────────┐           │
         └──────────────────────────┤ PAGE_COMM_STAT  │───────────┘
                                    │ (通信与发包统计)│
                                    └─────────────────┘
```

#### 各页面渲染内容与按键行为矩阵：

| 页面状态 (Menu State) | 显示核心内容 (Display Content) | KEY1 (上/递增) | KEY2 (下/递减) | KEY3 (操作/进入) | KEY4 (返回主页) |
|---|---|---|---|---|---|
| **PAGE_JOYSTICK** | X/Y 轴物理电压（0.00~3.30V）、X/Y 映射归一化值（-1000~+1000）、中心死区状态 | 循环切至 Page 4 | 切换至 Page 2 | 保持当前 / 触发摇杆当前值对齐 | 保持在 Page 1 |
| **PAGE_KEY_SW** | 4 个按键实时事件（Press/Release/Long/Double）、SW1/SW2 稳态高低电平 | 切换至 Page 1 | 切换至 Page 3 | 动作状态计数重置 | 返回 Page 1 |

| **PAGE_COMM_STAT** | 无线模块连接指示、累计外发数据包总数 (TX Count)、发送频率指示 | 切换至 Page 3 | 循环切至 Page 1 | **短按 KEY3 清零发包计数器** | 返回 Page 1 |

> **开源框架对齐说明**：本多级菜单行为与入库的 `驱动_框架/OLED_display/MiaoUI` 框架高度契合。MiaoUI 通过双向链表组织页面和菜单项，原生支持平滑非线性过渡动画与超长跑马灯。在后续实现阶段，上述 4 大核心页面将作为 MiaoUI 的根节点/子列表项注册，按键事件（`KEY1~KEY4`）直接映射为其导航与确认动作。

### 1.4 手柄数据流水线工作流 (Transmitter Data Pipeline)

手柄端正常运行时的数据流动采用非阻塞流水线驱动（详细任务时间轮与时间预算参见 [`TIMING_DESIGN.md`](file:///c:/Users/34118/Desktop/invc_exam/project/项目级_Prompt%20_Rules%20模板/TIMING_DESIGN.md)）：

```text
[定时触发 (固定 20ms / 50Hz 周期节拍)]
       │
       ▼
【Step 1: 模拟量获取】 ──► 读取 ADC1 DMA 内存缓冲区 ──► 扣除静态零偏 ──► 死区截断 ──► 计算 X.XX V 与归一化值 (耗时~45μs)
       │
       ▼
【Step 2: 姿态解算】   ──► SPI1 调用 LibDriver MPU6500 basic 接口读取原始 16 位寄存器 ──► 扣除陀螺仪零偏 ──► 本地软件滤波算法 (srv_imu_filter) 迭代 ──► 更新 Pitch/Roll/Yaw (【严禁使用 DMP】，耗时~280μs)
       │
       ▼
【Step 3: 状态装配】   ──► 读取按键当前状态位掩码与拨码开关电平
       │
       ▼
【Step 4: 协议封包】   ──► 组装数据帧：帧头 + 流水号(自增) + 长度 + CMD + 载荷数据 + 校验和/CRC + 帧尾
       │
       ▼
【Step 5: 无线外发】   ──► 通过 USART1 启动数据帧外发（无线模块为现成纯硬件透明透传，无需 AT 指令，写入串口即直接空中送达接收端），递增发包计数器 (耗时~80μs)
       │
       ▼
【Step 6: 本地诊断】   ──► 通过 USART2 格式化输出本地传感器数据日志（满足双串口评测比对要求，100ms周期）
```

> [!NOTE]
> **总线防死锁调度说明**：为彻底防止硬件 I2C 全屏刷新（1024 字节耗时 23ms）霸占 CPU 导致 10ms 按键任务饥饿，系统采用 **8 页分页切片刷屏机制**（每 12.5ms 刷新 1 页，单次仅耗时 2.8ms，整屏 100ms/10Hz 刷新，绝不阻断按键消抖与传感器采样）。详细时序甘特图参见 [`TIMING_DESIGN.md`](file:///c:/Users/34118/Desktop/invc_exam/project/项目级_Prompt%20_Rules%20模板/TIMING_DESIGN.md)。

## 第二部分：接收端系统行为设计 (Receiver Behavior)

> **核心通信事实**：两端无线透传模块为**现成硬件纯透明通道**，无需 MCU 进行任何无线配对或 AT 指令握手。手柄端 USART1 发出的数据流，接收端无线模块空中收到后直接输入接收端 MCU 的 `USART1_RX` 引脚并触发串口接收中断，行为与直连串口线完全一致。

### 2.1 接收端系统生命周期与工作模式 (Lifecycle & Operational Modes)

接收端系统行为围绕**“流式数据监听 $\rightarrow$ 校验分发 $\rightarrow$ 滑动窗口统计 $\rightarrow$ 双端同步呈现”**展开：

```text
               ┌───────────────────────┐
               │   POWER_ON / RESET    │ (上电复位)
               └──────────┬────────────┘
                          │
                          ▼
               ┌───────────────────────┐
               │  RECEIVER_INITIALIZE  │ (外设与显存初始化，清零统计器)
               └──────────┬────────────┘
                          │
                          ▼
               ┌───────────────────────┐
               │   WAIT_FIRST_PACKET   │ (等待无线首帧到达，显示等待提示)
               └──────────┬────────────┘
                          │ 收到并通过校验首帧
                          ▼
         ┌─────────────────────────────────┐
         │                                 │
         ▼                                 ▼
┌─────────────────────────┐       ┌─────────────────────────┐
│     LINK_CONNECTED      │       │      SIGNAL_LOST        │
│   (正常数据解析与统计)  │◄─────►│    (掉线/超时报警态)    │
└─────────────────────────┘       └─────────────────────────┘
```

#### 模式行为定义：
1. **WAIT_FIRST_PACKET (等待联机模式)**：
   - 接收端 OLED 显示 `"Receiver Ready"`, `"Waiting for Controller..."`；
   - 通信频率显示为 `0 Hz`，丢包率显示为 `0.0%`；
   - 环形缓冲区启动监听；一旦解出第一帧合法数据，记录首帧流水号，平滑切入 `LINK_CONNECTED`。
2. **LINK_CONNECTED (正常联机工作模式)**：
   - 持续从环形缓冲区弹出字节，驱动流式解包有限状态机；
   - 每收到有效帧：提取控制量与姿态角，累加 1 秒窗口有效计数，依据流水号推算丢包；即时通过 USART2 向上位机转发数据流；
   - 喂狗系统连接定时器（重置掉线计时）。
3. **SIGNAL_LOST (信号掉线/失联警告模式)**：
   - 若系统连接计时器超过 **$1000\text{ms}$（1.0秒）** 未能收到任何通过校验的有效数据包：
     - 系统自动判定为**通信掉线 (Signal Lost)**；
     - 瞬时有效通信频率归零（`Freq: 0 Hz`），丢包率指示置为 `100.0%` 或显示 `DISCONNECTED`；
     - OLED 显著闪烁提示通信中断警告；
     - 一旦无线信号恢复并成功解析出有效新帧，立即无缝自动重新联机恢复为 `LINK_CONNECTED`。

### 2.2 接收端核心状态机 1：流式解包有限状态机 (Stream Parser FSM)

为彻底解决无线信道中的**粘包、断包（半包）、噪声乱码注入**问题，接收端采用单字节驱动的确定性有限状态机：

```text
               ┌───────────────────────┐
               │     SEARCH_HEAD_1     │◄──────────────┐
               └──────────┬────────────┘               │
                          │ 遇到 0xAA                  │
                          ▼                            │
               ┌───────────────────────┐               │
               │     SEARCH_HEAD_2     │───────────────┤ (非 0x55 且非 0xAA)
               └──────────┬────────────┘               │
                          │ 遇到 0x55                  │
                          ▼                            │
               ┌───────────────────────┐               │
               │       READ_SEQ        │               │
               └──────────┬────────────┘               │
                          │ 存入序列号                 │
                          ▼                            │
               ┌───────────────────────┐               │
               │      READ_LENGTH      │───────────────┤ (长度超出预设安全范围)
               └──────────┬────────────┘               │
                          │ 长度有效                   │
                          ▼                            │
               ┌───────────────────────┐               │
               │       READ_CMD        │───────────────┤ (未知指令码)
               └──────────┬────────────┘               │
                          │ 指令合法                   │
                          ▼                            │
               ┌───────────────────────┐               │
               │     READ_PAYLOAD      │               │
               └──────────┬────────────┘               │
                          │ 收满 Length 字节           │
                          ▼                            │
               ┌───────────────────────┐               │
               │    CHECK_CHECKSUM     │───────────────┤ (校验比对失败，记录CRC错误)
               └──────────┬────────────┘               │
                          │ 校验匹配成功               │
                          ▼                            │
               ┌───────────────────────┐               │
               │      CHECK_TAIL       │───────────────┘ (尾字节不符)
               └──────────┬────────────┘
                          │ 尾字节完全匹配
                          ▼
               ┌───────────────────────┐
               │    DISPATCH_PACKET    │ ──► 更新全局遥测、丢包与帧率统计、触发PC转发
               └──────────┬────────────┘
                          │
                          └────────────────────────────► 回到 SEARCH_HEAD_1 继续消费后续字节
```

#### 抗粘包、断包与噪声注入的行为保障策略：
1. **连续粘包拆分行为**：当多帧数据粘连同时到达时，状态机完成当前帧的 `DISPATCH_PACKET` 后，**不重置缓冲区索引，而是立即在当前消费指针处切回 `SEARCH_HEAD_1`**，继续消化后续数据，自然拆包。
2. **断包（分段到达）保持行为**：若一帧数据跨越多次串口中断，状态机在当前状态（如 `READ_PAYLOAD` 读到一半）挂起，保留内部局部计数器，等待下一波串口数据入队后自动推进。
3. **噪声自动再同步行为**：在任何状态下一旦检测到非法字段（长度超标、未知命令字、校验失配、尾字节不对）：
   - 记录 1 次非法帧错误；
   - 状态机**无条件安全复位回 `SEARCH_HEAD_1`**，并从下一个字节重新检索，**绝不在死循环中等待**。

## 第三部分：系统交互协同与故障恢复行为设计

### 3.1 备用有线链路切换行为
* 当现场由于 433MHz/2.4G 无线信道干扰严重导致丢包率飙升或连接中断时，允许现场切换为杜邦线交叉直连：
  - 手柄 USART1_TX (PA9) $\leftrightarrow$ 接收端 USART1_RX (PA10)；
  - 手柄 USART1_RX (PA10) $\leftrightarrow$ 接收端 USART1_TX (PA9)；
  - 必须共地：手柄 GND $\leftrightarrow$ 接收端 GND。
* **软件自适应行为**：由于物理层与链路层完全解耦，软件协议与流式解包状态机无需任何重新编译或修改，接线后系统能在 $\le 1$ 个数据包时间内自动重新锁相通信。

### 3.2 异常与总线故障恢复行为
1. **I2C 总线死锁恢复行为**：若面包板由于接触不良导致 I2C 从机拉低 SDA 线卡死，I2C 驱动检测到超时错误后，软件自动产生复位脉冲释放总线，防止主程序卡死在 `HAL_I2C_Master_Transmit`。
2. **SPI 传感器离线恢复行为**：若 IMU 杜邦线脱落，读取函数超时退出，姿态解算模块自动进入安全降级状态，输出固定零姿态并持续在后台以低频（如 1Hz）尝试重新握手，线缆插回后自动恢复解算。
3. **串口溢出错误 (ORE) 恢复行为**：若主循环偶发高耗时导致 USART 硬件 FIFO 溢出触发 ORE 标志，串口中断例程自动读取 SR 与 DR 寄存器清除溢出错误，重新使能接收中断，防止串口彻底停止接收。
