# REQUIREMENTS.md — 工程需求规格说明书 (Step 1 需求分析 & Step 2 需求量化)

> **工序定位**：15步引导式开发流程的 **① 需求分析** 与 **② 需求量化**。  
> **核心使命**：将 2026年 INVC 嵌入式考核题目的“自然语言描述”全面转化为精确、可量化、可验证的“工程需求技术规格”，作为后续硬件资源映射、系统行为设计及软件架构设计的唯一输入基准。

## 第一部分：系统级工程需求分析 (① 需求分析 — 系统到底需要做什么？)

### 1.1 系统业务定位与总体使命
系统由**手柄发送端（Transmitter）**与**接收端（Receiver）**两套独立的 STM32F103C8T6 嵌入式硬件系统构成，全系统构建于**纯面包板手工插接**环境中。
* **手柄端使命**：实现多维物理控制量与运动传感器数据的精准感知与实时预处理（摇杆双轴电压采集、多按键事件滤波识别、拨码开关读取、SPI 六轴 IMU 本地姿态滤波解算），通过多级 OLED 菜单提供本地实时人机交互，按自定义二进制通信协议封装数据帧，通过无线串口模块向空中连续广播外发，并通过本地调试串口输出诊断日志。
* **接收端使命**：通过无线串口流式监听、接收手柄数据包，利用单字节容错状态机完成抗粘包、防断包与校验解析，以严格的 1 秒滑动窗口统计即时有效通信频率（Hz）与实时丢包率（%），通过本地 OLED 屏动态呈现控制量与通信统计指标，同时通过 USB 转 TTL 串口将数据转发至电脑上位机（如 VOFA+），呈现动态波形曲线或 3D 姿态立方体。

### 1.2 系统边界与数据流动拓扑

[2×拨码]   ──(稳态电平)──► [电平状态扫描]     │         │       (USART1)         (抗粘包/断包)      │    (实时数据显示)
[六轴IMU]  ──(SPI寄存器)─► [本地姿态滤波解算] ┘         │                                         │
                                                        ▼                                         ├──► [1秒窗口统计]

### 1.3 必须遵守的工程硬性红线与约束边界
1. **结构搭建红线**：100% 在面包板上手工插接完成，**严禁使用自制或成品 PCB**（违者直接取消评测资格）。
2. **通信外设红线**：全部通信接口必须采用 STM32 片上硬件外设（I2C1, SPI1, USART1, USART2），**严禁使用软件模拟 IIC、软件模拟 SPI 或软件模拟串口**。
3. **IMU 芯片红线**：必须使用 SPI 接口的六轴传感器，**严禁使用自带硬件 DMP 或已解算完毕的智能姿态模块**，姿态滤波解算必须在 STM32 本地由软件算法完成。
4. **物料成本红线**：除电池和无线模块外，全部硬件采购总成本 $\le 150.00$ 元（允许上浮 10%，总额上限为 $165.00$ 元），备齐发票凭证。
5. **供电安全红线**：供电电池必须选用**带保护板**的锂电池组，总电压 $\le 12.60\text{V}$，经降压模块后为系统供电。
6. **现场评测纪律**：评测期间**严禁连接 ST-Link/J-Link 烧录器**在线修改或烧录代码，仅能通过按复位键或重新拔插电源恢复运行。
7. **双串口联调红线**：评测现场必须同时接入并打印手柄端调试串口与接收端转发串口。
8. **交互性红线**：手柄端 OLED 必须支持多级菜单按键切换，单一静态页面直接计 0 分。
9. **通信有效性红线**：必须具备完整的自定义协议、粘包拆包与丢包处理逻辑，仅做原始透传直接计 0 分。

## 第二部分：子系统需求分析与需求量化矩阵 (② 需求量化 — 什么条件、什么时间、什么结果？)

### 2.1 摇杆模拟量采集工程需求 (Joystick ADC Acquisition)

| 维度 | 工程量化指标与技术规格 |
|---|---|
| **① 需求分析 (做什么)** | 连续采集双轴摇杆 X/Y 模拟电压，经 ADC 转换为数字量，同时计算出“归一化映射值”和“物理电压值”，供手柄 OLED 屏幕显示与串口输出，接受示波器波形比对检验。 |
| **【输入条件】** | 1. 物理信号：2 路模拟电位器中心抽头电压，输入电压范围 $0.00\text{V} \sim 3.30\text{V}$；<br>2. 硬件外设：STM32 片上 ADC1，规则组通道 0 (PA0-WKUP) 与通道 1 (PA1)；<br>3. 转换精度：12-bit 分辨率，数值范围 $0 \sim 4095$；<br>4. 时钟源：PCLK2 (72MHz) 6分频 = 12MHz（严格在 14MHz 安全上限内）。 |
| **【时间条件】** | 1. 通道采样周期：55.5 Cycles（单通道转换总时间 $55.5 + 12.5 = 68$ 周期 $\approx 5.67\mu\text{s}$）；<br>2. 连续采样周期：DMA 循环模式持续自动刷新；<br>3. 物理响应时延：从物理拨动摇杆到串口与 OLED 刷新可见的时延 $t_{\text{resp}} \le 50\text{ms}$。 |
| **【结果与精度要求】** | 1. **物理电压计算**：$V_{\text{actual}} = \frac{\text{ADC\_RAW}}{4095} \times 3.30\text{V}$，以 `X.XX V` 格式显示（保留两位小数），电压测量绝对误差 $\le \pm 0.05\text{V}$；<br>2. **归一化映射值**：线性映射至整数范围 $[-1000, +1000]$，机械中心静态时具有 $\pm 50$ 的死区滤除保护，极左/极下为 $-1000$，极右/极上为 $+1000$；<br>3. **双端同步输出**：手柄 OLED 屏幕与手柄 USART2 调试串口同时输出上述数值。 |
| **【验收判定准则】** | 1. 示波器探头接 PA0/PA1 观测输出引脚波形，电压跳变平稳，静态抖动峰峰值 $V_{\text{pp}} \le 100\text{mV}$；<br>2. 串口打印电压值与示波器实测直流电压比对，绝对偏差 $\le 0.05\text{V}$；<br>3. 摇杆从一端推至另一端，映射值单调平滑变化，无剧烈跳变。 |

### 2.2 按键与开关检测工程需求 (Key & Switch Scanning)

| 维度 | 工程量化指标与技术规格 |
|---|---|
| **① 需求分析 (做什么)** | 监测 $\ge 4$ 个独立轻触按键与 $\ge 2$ 个拨码开关。按键需滤除机械抖动并准确识别 4 种互斥事件（按下、释放、长按、双击）；拨码开关需稳定输出高低电平稳态。 |
| **【输入条件】** | 1. 4 个按键引脚（PB0, PB1, PB10, PB11）配置为内部弱上拉输入（PULLUP），未按时高电平（$\ge 2.0\text{V}$），按下闭合接地为低电平（$\le 0.8\text{V}$）；<br>2. 2 个拨码开关引脚（PB12, PB13）配置为内部弱上拉输入，拨至 ON 接地（低电平），拨至 OFF 悬空（高电平）。 |
| **【时间条件】** | 1. **软件消抖窗口**：连续有效电平持续时间 $t_{\text{debounce}} \in [15\text{ms}, 30\text{ms}]$，彻底滤除 $< 15\text{ms}$ 的接触抖动；<br>2. **短按识别时间**：按压保持时间 $t \in [30\text{ms}, 1999\text{ms}]$；<br>3. **长按识别硬性指标**：持续保持按下时间 **$t_{\text{long}} \ge 2000\text{ms}$ (2.0秒)**，达到 2.0s 瞬间立即触发长按事件（无需等待抬起）；<br>4. **双击判定时间窗口**：连续两次短按抬起与再次按下的间隔时间 **$t_{\text{double}} \le 300\text{ms}$**，超过 300ms 则判定为两次独立的单击事件；<br>5. **拨码开关采样滤波**：连续采样 3 次电平一致（确认时间 $\ge 50\text{ms}$）判定为稳态。 |
| **【结果与格式要求】** | 1. **按键事件输出**：每个按键独立输出 4 种枚举状态：`PRESS`（按下）、`RELEASE`（释放）、`LONG_PRESS`（长按）、`DOUBLE_CLICK`（双击）；<br>2. **开关状态输出**：稳定输出二值电平状态：`ON` (0) / `OFF` (1)；<br>3. **状态呈现**：手柄 OLED 菜单中实时更新按键/开关状态，手柄 USART2 调试串口打印事件触发日志。 |
| **【验收判定准则】** | 1. 快速连续点击 10 次，不产生多击误判或漏判；<br>2. 按住按键精确超过 2.0 秒，屏幕和串口立即跳出长按提示，松手时不误触单击释放；<br>3. 快速双击操作下，100% 准确捕获双击事件，不误触发两次单击；<br>4. 拨码开关拨动时，稳态高低电平识别准确率 100%。 |

### 2.3 OLED 层次化多级菜单工程需求 (OLED Multi-Level Menu System)

| 维度 | 工程量化指标与技术规格 |
|---|---|
| **① 需求分析 (做什么)** | 采用硬件 I2C 驱动 0.96 寸 OLED，构建支持按键交互的层次化多级菜单页面，涵盖摇杆、按键/开关、姿态角及通信状态，严禁单一静态页展示。 |
| **【输入条件】** | 1. 硬件外设：STM32 片上硬件 I2C1（PB6: SCL, PB7: SDA），Fast Mode (400kHz)，开漏复用；<br>2. 屏幕规格：0.96 英寸，分辨率 $128 \times 64$ 像素，单色显示，显存占用 $128 \times 64 / 8 = 1024\text{ 字节}$；<br>3. 导航按键输入：来自按键识别模块的触发事件（如 KEY1 上翻、KEY2 下翻、KEY3 确认/切换、KEY4 返回）。 |
| **【时间条件】** | 1. 显存全屏总线传输耗时：$1024\text{ 字节} \times 9\text{ 位} / 400\text{kbps} \approx 23.04\text{ms}$；<br>2. 屏幕刷新率：控制在 $10\text{Hz} \sim 20\text{Hz}$（刷新周期 $50\text{ms} \sim 100\text{ms}$），避免总线持续饱和；<br>3. 界面切页响应延迟：按键按下至屏幕切换完成 $t_{\text{menu\_switch}} \le 100\text{ms}$。 |
| **【结果与页面覆盖】** | 必须实现至少包含以下 4 类内容的层次化菜单体系：<br>1. **摇杆监测页 (Page 1)**：显示 X 轴/Y 轴物理电压值（精确到 0.01V）与映射数值；<br>2. **按键开关页 (Page 2)**：显示 4 个按键的即时动作事件（按下/释放/长按/双击）与 2 位拨码开关稳态电平；<br>3. **姿态监控页 (Page 3)**：显示解算出的实时 Pitch（俯仰）、Roll（横滚）、Yaw（偏航）角度值（精确到 0.1°）；<br>4. **通信状态页 (Page 4)**：显示无线连接状态、累计发送数据包计数（Packet Counter）。 |
| **【验收判定准则】** | 1. 评委现场按键操作，多级菜单能在各页面间顺畅往复切换，无死机、花屏或错位；<br>2. **若 OLED 始终仅展示单一静态页面，本项直接计 0 分**。 |

### 2.4 六轴 IMU 驱动与姿态解算工程需求 (IMU Driver & Attitude Estimation)

| 维度 | 工程量化指标与技术规格 |
|---|---|
| **① 需求分析 (做什么)** | 采用硬件 SPI 驱动六轴 IMU，读取原始加速度与角速度寄存器数据，在本地软件算法中完成零偏校准与姿态融合滤波，稳定解算输出 Pitch、Roll、Yaw 姿态角。严禁使用自带 DMP 解算模块。 |
| **【输入条件】** | 1. 硬件外设：STM32 片上硬件 SPI1 主机全双工模式（PA5: SCK, PA6: MISO, PA7: MOSI），Motorola Mode 0 (CPOL=0, CPHA=0)；<br>2. 软件片选引脚：PA4 (推挽高速输出，高电平未选通，低电平使能片选)；<br>3. 通信速率：PCLK2 (72MHz) 8分频 = 9.0 MBits/s；<br>4. 传感器类型：SPI 接口六轴传感器（3轴加速度计 + 3轴陀螺仪），严禁使用带 DMP/已出厂解算姿态角的模块。 |
| **【时间条件】** | 1. 传感器采样与姿态更新周期：推荐 $50\text{Hz} \sim 100\text{Hz}$ ($10\text{ms} \sim 20\text{ms}$)；<br>2. 上电静止零偏校准窗口：上电后静止采样 $1.0\text{s} \sim 2.0\text{s}$ 自动完成零偏均值扣除。 |
| **【结果与精度要求】** | 1. **原始数据采集**：三轴加速度 Acc_X/Y/Z（16-bit 有符号整数）、三轴角速度 Gyro_X/Y/Z（16-bit 有符号整数）；<br>2. **姿态角度输出范围与分辨率**：<br>   - 俯仰角 Pitch：范围 $[-90.0^\circ, +90.0^\circ]$，静态漂移 $\le \pm 1.0^\circ$，分辨率 $0.1^\circ$；<br>   - 横滚角 Roll：范围 $[-180.0^\circ, +180.0^\circ]$，静态漂移 $\le \pm 1.0^\circ$，分辨率 $0.1^\circ$；<br>   - 偏航角 Yaw：基于陀螺仪 Z 轴积分相对偏航角，静止漂移受控，分辨率 $0.1^\circ$；<br>3. **滤波调优加分项**：针对零偏与噪声特性调优滤波参数（如互补滤波系数或卡尔曼参数），在报告中给出原始值与滤波值对比曲线，现场演示动态响应。 |
| **【验收判定准则】** | 1. 手柄在空间水平、翻滚、俯仰倾斜时，OLED 与上位机显示的角度值顺滑连续变化，静止时不发生剧烈跳变或发散；<br>2. 拔掉 SPI 杜邦线或短接时，代码具备超时容错机制，不会卡死单片机主循环。 |

### 2.5 自定义通信协议与传输机制工程需求 (Custom Protocol & Transmission)

| 维度 | 工程量化指标与技术规格 |
|---|---|
| **① 需求分析 (做什么)** | 自行设计全双工/半双工二进制通信帧协议，在手柄端完成结构化封包并周期外发；接收端进行流式解析，具备完善的粘包拆包与丢包处理机制，支持杜邦线交叉直连备用验证。 |
| **【输入条件】** | 1. 硬件外设：两端片上硬件 USART1（PA9: TX, PA10: RX），波特率 115200 8N1，使能全局接收中断；<br>2. 物理介质：无线透传模块（正常通道） / 交叉杜邦线（备用直连通道：TX接RX，RX接TX，共地）。 |
| **【时间条件】** | 1. 手柄发送频率：推荐 $20\text{Hz} \sim 50\text{Hz}$（即每隔 $20\text{ms} \sim 50\text{ms}$ 发送一帧）；<br>2. 接收解包处理时延：完整接收帧尾后在 $t_{\text{parse}} \le 2\text{ms}$ 内完成解析校验与数据分发。 |
| **【协议要素与结构量化】** | 自定义通信帧必须 100% 包含以下全部 6 类核心要素：<br>1. **帧头 (Frame Header)**：$\ge 2$ 字节固定特征码（抗随机噪声，如双字节同步码）；<br>2. **有效数据长度 (Length)**：1 字节，显式指示后续数据载荷字节数；<br>3. **功能码 (CMD / Function Code)**：1 字节，区分数据帧类型；<br>4. **数据载荷 (Payload)**：承载摇杆值、按键开关位掩码、姿态三轴角度；<br>5. **校验字段 (Checksum / CRC)**：采用 CRC 或累加和，覆盖流水号至载荷全部字节；<br>6. **帧尾 (Frame Tail)**：$\ge 1$ 字节固定结束边界标识。 |
| **【解包与抗干扰量化】** | 1. **粘包处理**：当一次串口缓冲读取到多个连续帧时，流式状态机逐包完整拆分并连续处理；<br>2. **断包/半包处理**：跨中断到达的数据段由接收缓冲区持续暂存，直到匹配完整帧长度与帧尾；<br>3. **噪声自动恢复**：遇到信道误码或非法字节时，状态机在 $\le 1$ 字节内立即复位，重新检索前导帧头，不发生死循环或数据乱码；<br>4. **丢包追踪策略**：采用递增流水号（Sequence ID）追踪丢包，支持丢包重传/超时重发或连续流水号丢包统计策略。 |
| **【验收判定准则】** | 1. 设计报告中必须以独立章节详细阐述帧结构定义、设计理由及校验算法选择依据；<br>2. 选手必须在评测现场向评委清晰阐述协议逻辑、校验原理及粘包/丢包处理策略（无法清晰阐述者，通信部分最高仅得 50% 分数）；<br>3. 严禁仅使用无线模块透传原始数据而不进行本地打包解析，违者直接计 0 分。 |

### 2.6 接收端数据统计与上位机可视化工程需求 (Receiver Statistics & PC Visualization)

| 维度 | 工程量化指标与技术规格 |
|---|---|
| **① 需求分析 (做什么)** | 接收端解析手柄数据后，统计过去 1 秒内有效包通信频率（Hz）与实时丢包率（%），在本地 OLED 上刷新显示；同时通过 USB 转 TTL 串口将数据转发至电脑上位机（如 VOFA+），呈现动态波形或 3D 姿态立方体。 |
| **【输入条件】** | 1. 数据来源：接收端 USART1 成功解包的有效遥测数据帧；<br>2. 硬件外设：接收端硬件 I2C1 驱动 0.96 寸 OLED，接收端硬件 USART2（PA2: TX, PA3: RX, 115200 8N1）连接 USB 转 TTL 模块。 |
| **【时间条件】** | 1. **频率与丢包率统计窗口**：严格以 **$1000\text{ms}$ (1.0 秒)** 为统计与刷新周期；<br>2. 接收端 OLED 刷新周期：$100\text{ms} \sim 200\text{ms}$；<br>3. 上位机转发时延：有效包到达后即收即转，转发延迟 $t_{\text{forward}} \le 5\text{ms}$。 |
| **【计算模型与量化指标】** | 1. **通信频率统计 (Hz)**：接收端统计 1 秒内成功通过校验的有效数据包总数 $N_{\text{valid}}$，数值即为即时频率 $\text{Hz}$（整数）；<br>2. **丢包率统计 (%)**：依据连续两包的流水号差值计算丢包数：<br>   $$\text{Lost} = (\text{ID}_{\text{current}} - \text{ID}_{\text{last}} - 1) \pmod{256}$$<br>   在 1 秒统计窗口内计算实时丢包率百分比：<br>   $$\text{Loss\_Rate} = \frac{\sum \text{Lost}}{N_{\text{valid}} + \sum \text{Lost}} \times 100\%$$<br>   显示格式：`XX.X %`（保留 1 位小数）；<br>3. **接收端屏幕显示指标**：OLED 实时显示手柄端发送的摇杆值、按键/开关状态、姿态角，并显式标注当前通信频率 `Freq: XX Hz` 与丢包率 `Loss: X.X %`；<br>4. **上位机可视化**：USART2 向上位机输出符合规范的数据流，电脑端上位机软件（如 VOFA+）成功渲染出动态波形曲线或 3D 姿态立方体。 |
| **【验收判定准则】** | 1. 电脑串口助手观察接收端 1 秒打印的包计数，与手柄端发送频率完全吻合（误差 $\le \pm 1\text{Hz}$）；<br>2. 人为遮挡天线或制造间歇干扰时，接收端 OLED 上的丢包率数值灵敏上升，恢复后丢包率迅速归零；<br>3. 上位机动态波形或 3D 姿态立方体跟随手柄空间转动实时平滑响应。 |

## 第三部分：硬件、安全与系统级硬约束量化指标

| 约束维度 | 自然语言描述要求 | 工程量化指标与判定红线 |
|---|---|---|
| **面包板搭接** | 全部硬件在面包板上手工插接完成 | **成品 PCB 或打样 PCB 使用率必须为 0%**，全系统使用杜邦线/跳线插接。 |
| **物料成本上限** | 除电池与无线模块外，物料总价不超过 150 元 | 采购发票总金额 $\le 150.00$ 元（允许超限 10%，绝对总上限为 **$165.00$ 元**）。 |
| **IMU 硬件通信** | 必须使用 SPI 接口，禁止使用解算好的芯片 | 必须连接片上 SPI1 外设（芯片已确认为 **MPU6500**，参考 LibDriver basic 模式读取原始值），**严禁使用片上硬件 DMP 解算，姿态必须在 MCU 本地由软件滤波算法解算**。 |
| **供电安全** | 电池必须选用带保护板的锂电池组 | 锂电池组具备过充/过放保护板，端电压 **$U_{\text{batt}} \le 12.60\text{V}$**，严禁软包无保护板电池。 |
| **片上硬件外设** | 只能采用硬件通信，不得采用软件模拟通信 | 软件模拟 I2C、软件模拟 SPI、软件模拟串口使用率必须为 **0%**。 |
| **现场代码修改** | 正式评测期间严禁连接烧录器 | 评测时 ST-Link / J-Link 物理连接率为 **0%**，仅允许物理复位或重新插拔电源。 |
| **双串口输出** | 手柄端调试串口与接收端转发串口同时连接电脑 | 评测时必须有 2 条独立的 USB-TTL 串口线同时接电脑并打印，缺少任一端即扣分。 |
| **MCU 栈空间配置**| 避免显存局部变量导致栈溢出 | CubeMX 工程 `Minimum Stack Size` 显式配置为 **`0x800` (2048 字节 / 2KB)**。 |

## 第四部分：可验证工程验收核对矩阵 (Acceptance Checklist)

### 1. 手柄发送端验收项
- [ ] **CHKL-TX-01 [摇杆电压输出]**：摇杆 X/Y 轴输出正常，OLED 和调试串口均能同时看到原始映射值（如 -1000~+1000）与物理电压值（精确到 0.01V）。
- [ ] **CHKL-TX-02 [示波器波形比对]**：示波器实测摇杆输出波形平滑稳定，无剧烈毛刺，物理电压与串口打印值绝对误差 $\le 0.05\text{V}$。
- [ ] **CHKL-TX-03 [按键单击按下]**：KEY1~KEY4 任意按下时，消抖可靠无误触发，准确识别按下事件。
- [ ] **CHKL-TX-04 [按键释放]**：KEY1~KEY4 抬起时，准确识别释放事件。
- [ ] **CHKL-TX-05 [长按 $\ge 2.0\text{s}$]**：任意按键长按持续超过 2.0 秒，达到 2.0s 瞬间准确触发长按事件，松手时不误触单击。
- [ ] **CHKL-TX-06 [快速双击]**：300ms 窗口内连续两次按下，准确识别为双击事件，不误判为两次单击。
- [ ] **CHKL-TX-07 [拨码稳态]**：SW1、SW2 拨动时，高低电平稳态在屏幕上准确显示。
- [ ] **CHKL-TX-08 [多级菜单切换]**：OLED 能通过按键在摇杆页、按键状态页、姿态角页、通信统计页之间自由流畅切换，**绝非单一静态页**。
- [ ] **CHKL-TX-09 [SPI 读 IMU]**：硬件 SPI1 成功读取 IMU 原始加速度与角速度寄存器数据。
- [ ] **CHKL-TX-10 [姿态滤波解算]**：手柄端稳定计算并输出 Pitch、Roll、Yaw 角度，手柄倾斜时角度顺畅连续变化，静止时不发散。
- [ ] **CHKL-TX-11 [手柄调试打印]**：手柄端 USART2 以 115200 波特率稳定输出本地传感器采集与状态日志。

### 2. 接收端与通信链路验收项
- [ ] **CHKL-COM-01 [协议帧完整性]**：手柄端与接收端建立无线通信，数据帧完整包含帧头、长度、功能码、载荷、校验字段、帧尾 6 大要素。
- [ ] **CHKL-COM-02 [流式拆包与抗干扰]**：手柄连续外发，接收端连续解析，人为注入噪声或断开杜邦线后重连，状态机能在 $\le 1$ 字节内重新同步帧头。
- [ ] **CHKL-COM-03 [备用直连通道]**：现场支持快速切换为杜邦线交叉直连测试（TX-RX, RX-TX, GND）。
- [ ] **CHKL-RX-01 [接收端 OLED 显示]**：接收端 OLED 实时刷新显示从手柄接收到的摇杆、按键、开关及姿态角数据。
- [ ] **CHKL-RX-02 [1秒频率统计 Hz]**：接收端每隔 1000ms 统计一次有效包数量并在屏幕与串口上输出通信频率（Hz）。
- [ ] **CHKL-RX-03 [1秒丢包率统计 %]**：接收端每隔 1000ms 根据流水号差值计算实时丢包率（%），遇信道干扰时丢包率灵敏上升。
- [ ] **CHKL-RX-04 [上位机动态可视化]**：接收端 USART2 向上位机电脑转发数据，VOFA+ 或串口助手成功呈现平滑动态曲线图或 3D 姿态立方体。

### 3. 规范与安全验收项
- [ ] **CHKL-GEN-01 [纯面包板搭接]**：全系统为纯面包板手工走线，未使用任何自制打样或商用成品 PCB。
- [ ] **CHKL-GEN-02 [物料成本合规]**：除电池和无线外，采购发票总金额 $\le 165.00$ 元。
- [ ] **CHKL-GEN-03 [电池安全合规]**：供电锂电池组带保护板且端电压 $\le 12.60\text{V}$。
- [ ] **CHKL-GEN-04 [纯硬件外设]**：通信全部采用片上硬件外设（I2C1, SPI1, USART1, USART2），无软件模拟。
- [ ] **CHKL-GEN-05 [双串口在线]**：手柄端与接收端同时连接电脑 USB-TTL 并同时输出日志。
- [ ] **CHKL-GEN-06 [免烧录运行]**：评测期间不接入 ST-Link/J-Link 烧录器，系统完全脱机独立运行。
