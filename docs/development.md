# 开发流程与维护约定

[文档导航](README.md) · [当前状态](project-status.md) · [早期规则原文](archive/early-design/development-rules.md)

本页整理用户已经说明的工作方式和现有工程约束。任务范围以用户当前请求为准；历史文档是背景材料，不替代用户授权。

## 按步骤推进

| 阶段 | 步骤 |
|---|---|
| 需求与设计 | ① 需求分析；② 量化；③ 硬件映射；④ 系统行为；⑤ 架构；⑥ 模块；⑦ 接口；⑧ 数据；⑨ 时序；⑩ 异常与边界 |
| 软件实现 | ⑪ 状态机与关键逻辑；⑫ 驱动层实现与验证；⑬ 业务层实现；⑭ 联调与优化 |
| 最终交付 | ⑮ 结合实际硬件验收与个人报告整理最终版本 |

⑪～⑭ 采用用户最近明确使用的名称；旧文档中的“模块测试/功能联调/系统测试/Code Review”属于历史编号，避免在当前进度中混用。

先完成当前阶段的实现和对应验证，再进入下一阶段。用户明确授权连续完成多个步骤时，可以同一轮逐步推进，无需把历史“一次对话一步”理解为必须中途停止。遇到影响正确性的缺失信息应及时询问，不假定器件性能、接线或硬件已经验证。本次 C++ 重构以用户已上板验证的当前代码为基线，保留业务行为；不将前一轮副本当成最新代码。

## 编码边界

| 主题 | 约定 |
|---|---|
| 修改前检查 | 先读实际源码、头文件及调用链，不根据名字猜 API 或行为 |
| 架构 | 保留裸机分层；App 使用 C++17，HAL/BSP/Service/Core 保持 C；main 只初始化与调度，不引入无关 RTOS/文件系统 |
| CubeMX | Core 改动放 USER CODE 区或独立文件；不改生成初始化签名；重生成后核对运行时覆盖 |
| 资源 | 64 KB Flash、20 KB SRAM、2 KB 栈预算；显存/队列静态分配，业务不动态分配内存 |
| 中断 | 只清状态、搬数据和置标志；解析、滤波、显示、打印放主循环；共享状态考虑 volatile 与原子访问 |
| 时序 | 时间戳/状态机推进等待；检查短 HAL 事务的返回值与超时，不用长延时堵住业务 |
| 缓冲 | 校验长度、空参数、索引、所有权；异步发送不能引用短生命周期局部缓冲 |
| 通信 | 使用硬件 I2C/SPI/UART；无线为透明通道，不新增无依据的 AT/配对流程 |
| IMU | 只读原始数据，在 MCU 软件解算，不使用 DMP；当前采用精简寄存器驱动 |
| 第三方资料 | 保留原参考源码，业务经 BSP 隔离；现代码并不强制依赖 LibDriver basic 或 MiaoUI |

## 修改后的对应检查

| 修改内容 | 同步内容与检查 |
|---|---|
| 帧布局、校验、ACK | 双端 srv_protocol、srv_link/接收 App、[协议文档](protocol.md)、PC 说明与协议测试 |
| 输入、滤波、统计 | 对应 Service 测试及[架构](architecture.md)/[参数](hardware-configuration.md) |
| 引脚、驱动、NVIC | 确认本地 HAL/芯片手册；驱动模拟测试、CubeMX 用户区和硬件待测清单 |
| 新增业务源文件 | 更新相应 CMake target_sources；运行两端 Debug/Release 构建，不再维护 Keil 清单 |
| 菜单、日志、PC 通道 | [使用说明](user-guide.md)、业务/集成测试，必要时生成显存预览 |
| 仅文档与重命名 | 核对源码事实、相对链接、引用/迁移表；不必重复运行无关固件测试 |

使用 `.clang-format` 的现有格式。C++ 不使用动态分配、异常、RTTI 或复杂继承；构造时不访问硬件，使用静态实例与显式 init。协议和共用驱动副本不能只改一端。测试入口见[构建与复测](quick-start.md)；检查通过后说明改动、验证方式及尚未验证的边界，不使用“完全稳定”等没有证据的结论。

## 文档维护

- 当前文档只维护一个主要主题：帧字节表在 protocol，PC 通道在 user-guide，参数在 hardware-configuration，状态在 project-status。
- API 细节链接到头文件，避免复制整套声明后与源码分叉。短说明应交代返回值、所有权或调用上下文。
- 使用中文标题、英文小写连字符文件名和相对链接；跨目录引用随重命名一起更新。
- 记录以 `YYYY-MM-DD-topic.md` 命名，写清工具、命令、场景、结果和限制。后续结果追加新记录，勿将旧实验改写成新结论。
- 历史设计保留在 archive，并提供指向当前文档的醒目标识；原题与第三方目录保留原位置。


## 行为不变的重构验收

迁移状态/接口时保留判断条件、初始化顺序、任务调用顺序、HAL_GetTick 位置、浮点运算、缓冲大小和序列化格式。先保存当前 C 基线，再执行原测试与 `test_cpp_equivalence.py` 的同输入对照；比较 UART 字节、状态/计数及显存，不要求 ELF/BIN 相同。新的硬件测量应单独记录，不能将主机对照称为重构后的上板验收。
