#### 1. 物理层双串口拓扑隔离成果

* **手柄端通道 A（USART1: PA9/PA10）**：专职对接无线串口透传模块，负责自主协议数据帧的发送，开启全局中断。

* **接收端通道 B（USART2: PA2/PA3）**：专职连接 USB 转 TTL，向上位机（VOFA+）高速转发可视化格式数据包。

### 三、 底层外设工程参数与关键避坑实现

#### 1. 时钟树全频规划与总线合规性

* 两端 MCU 外部 8MHz 晶振通过内部 PLL 9 倍频锁定 **SYSCLK / HCLK 为 72MHz** 满频运行。


* AHB 总线不分频（72MHz），Flash 延时配置为 2WS（3个 CPU 周期）以匹配高速时钟。


* APB1 低速总线设为 2 分频（**36MHz**，符合 36MHz 上限限制），I2C1 与 USART2 挂载于此总线；APB2 高速总线保持 72MHz。


* 手柄端 ADC 预分频器配置为 6 分频，ADC 转换时钟锁定为 **12MHz**（严格控制在 14MHz 安全工作上限以内）。



#### 2. 模拟摇杆 ADC1 + DMA1 自动化采集闭环

* ADC1 规则组配置了 2 个转换通道（Rank1 为 Channel 0，Rank2 为 Channel 1），采样周期均设置为 55.5 Cycles。


* 使能 `Scan Conversion Mode`（扫描转换）与 `Continuous Conversion Mode`（连续转换）。


* 绑定 `DMA1_Channel1` 为循环模式（Circular），外设地址固定，内存地址使能自增，传输位宽均为 Half Word（16 位）。ADC 启动后持续将采样值更新至静态内存，无需 CPU 频繁干预。



#### 3. 纯硬件通信协议电气规范

* **I2C1 外设**：采用硬件外设开漏复用输出（Alternate Function Open Drain），通信时钟配置为 400000 Hz（Fast Mode），提升 OLED 全屏刷新帧率，避免滚屏撕裂感。


* **SPI1 外设**：采用硬件全双工主机模式，SCK、MOSI 设为复用推挽，MISO 设为浮空输入；通信波特率预分频设为 8 分频（9.0 MBits/s），时序严格匹配 CPOL=Low, CPHA=1 Edge（Mode 0）。软件片选引脚 PA4（`MPU_CS`）的最大输出速度设为 High，保证片选边沿陡峭度。



#### 4. 运行时内存安全保障

* 两端工程在 CubeMX 中将 `Minimum Stack Size` 显式设为 **`0x800`（2048 字节）**，避免 OLED 显存缓冲区（1024 字节）在局部变量操作中或发生双串口与 DMA 中断嵌套时造成栈溢出崩溃（HardFault）。


* `Minimum Heap Size` 维持 `0x200`（512 字节）。

### 四、 已确立的通信链路协议与算法处理规范

针对考核对自定义帧结构、封包解包机制及丢包/帧率统计的要求，已确定采用 18 字节固定长度二进制数据帧体系。

#### 1. 通信帧结构定义（手柄端 $\rightarrow$ 接收端）

```c
#pragma pack(push, 1)
typedef struct {
    uint8_t  header[2];    // 帧头：固定 0xAA, 0x55 (双字节抗随机噪声)
    uint8_t  packet_id;    // 帧序列号：0~255 循环累加 (用于接收端丢包率统计)
    uint8_t  length;       // 载荷长度：固定 0x0B (11 字节 Payload)
    uint8_t  cmd;          // 命令码：0x01 (综合遥测数据帧)
    
    /* 数据载荷 Payload (11 字节) */
    int16_t  joy_x;        // 摇杆 X 轴归一化值 (-1000 ~ +1000)
    int16_t  joy_y;        // 摇杆 Y 轴归一化值 (-1000 ~ +1000)
    uint8_t  key_sw_bits;  // 按键与开关位掩码:
                           // Bit0~3: KEY1~KEY4 状态 (1按下, 0释放)
                           // Bit4~5: SW1~SW2 状态 (1高, 0低)
                           // Bit6~7: 保留位
    int16_t  pitch;        // 姿态俯仰角 (物理角度 * 100，例如 25.40° 存储为 2540)
    int16_t  roll;         // 姿态横滚角 (物理角度 * 100)
    int16_t  yaw;          // 姿态偏航角 (物理角度 * 100)
    
    /* 校验与帧尾 */
    uint8_t  checksum;     // 校验和：packet_id 至 yaw 的 14 字节无符号单字节累加和
    uint8_t  tail;         // 帧尾：固定 0xED
} TelemetryFrame_t;
#pragma pack(pop)

```

#### 2. 解包状态机机制

接收端采用单字节流式驱动的有限状态机（FSM）接收数据：

```
[等待帧头1 0xAA] ──► [等待帧头2 0x55] ──► [读取流水号 ID] ──► [校验载荷长度 0x0B]
       ▲                      ▲
       └──────(匹配失败)───────┴──► [读取数据载荷 Payload] ──► [累加和校验] ──► [校验帧尾 0xED]
                                                                                │
                                                                                ▼
                                                                     【触发有效包处理与统计】

```

此机制可在无线传输发生字节粘连、零星丢字节或外界噪声干扰时，实现逐字节同步检索与自动重置，避免整段数据解析失效。

#### 3. 统计模型数学定义

* **通信频率统计（Hz）**：接收端以 1000ms 定时器作为统计窗口，统计 1 秒内成功通过校验并解包的有效帧总数即为即时频率 $f$（Hz）。


* **丢包率统计（%）**：利用接收到的前后两帧流水号差值计算丢包：

$$\text{Lost} = (ID_{\text{current}} - ID_{\text{last}} - 1) \pmod{256}$$



在 1 秒统计窗口内计算实时丢包率：

$$\text{Packet\_Loss\_Rate} = \frac{\sum \text{Lost}}{\text{Received\_Count} + \sum \text{Lost}} \times 100\%$$

### 六、 核心外设参考驱动与框架入库资产清单 (驱动_框架/)

   * **定位**：工业级、跨平台、符合 MISRA C 规范的 MPU6500 六轴惯性传感器 C 驱动。

   * **业务模式**：采用 `driver_mpu6500_basic.c` 轮询读取原始 16 位加速度计与陀螺仪数据。
   * **合规红线**：**严禁使用 DMP**！禁止调用 `driver_mpu6500_dmp.c/.h`，所有姿态解算均由本地软件层（`srv_imu_filter`）完成。

2. **0.96寸 OLED 屏幕底层驱动例程 (`驱动_框架/OLED_display/底层驱动源码/.../01-0.96OLED显示屏STM32F103C8T6_IIC例程/`)**：

   * **核心资产**：复用 SSD1306 初始化命令序列、1KB 显存全屏刷写机制、`oledfont.h` (6×8 / 8×16 ASCII 字模)。
   * **总线适配**：将例程中的软件模拟 GPIO 翻转重构为调用 CubeMX 配置好的片上硬件 I2C1（PB6/PB7 400kHz Fast Mode）。
