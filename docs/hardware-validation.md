## 建议验证顺序

先确认各外设独立工作，再用双向串口直连核对协议，随后替换为无线透明模块，最后同时观察两端 OLED 与 PC 串口。原题要求的现场纪律、硬件搭建与供电条件以原始题目为准。

|---|---|---|

## 数据解释

有效新遥测频率与重复到包频率分别统计；PC 等待/离线快照不算新遥测。长时间离线后序号基准重建，最终丢包率不能完整反映断链期间所有缺帧。无线时延变大时停止等待会降低新帧频率，这与串口波特率可用带宽不是同一指标。

Yaw 是相对偏航，会漂移；ADC 3300 mV 是换算默认参考，不是对供电实测值的声明。旧设计中的 ≤50 ms 响应、≤100 ms 切页、固定电压/角度误差等不能在没有测量时勾选达标。

## 每次实验记录

在 `docs/records/` 新建带日期的记录，可使用以下字段：

| 字段 | 填写内容 |
|---|---|
| 时间与版本 | 测试日期、源码版本/改动范围、固件标识 |
| 环境 | 板卡、模块、供电实测、接线、串口和观测工具 |
| 参数 | 本次实际生效的校准/滤波/重传参数 |
| 操作与预期 | 可重复的操作步骤及判定依据 |
| 观测结果 | 原始串口日志、曲线/截图、测量值，不只写“正常” |
| 结论与后续 | 通过/失败/待复查，问题原因与修复后的复测结果 |

完成实际验证后更新[项目状态](project-status.md)，并将原始测量证据与结果记录一并保留。
