# 操作与上位机

[文档导航](README.md) · [通信协议](protocol.md) · [硬件验证](hardware-validation.md)

以下说明对应当前软件行为。实际板卡和 PC 串口连接尚未联调；引脚见[硬件映射](hardware-configuration.md)。

## 上电与校准

1. 发送端上电后保持静止，等待收集 100 个合格 IMU 样本。运动、重力模长异常或方差超标会重置校准窗口。
2. 启动前 1500 ms 不发遥测，采样、界面与校准照常进行；这段静默用于对端重新建立序号基准。
3. 进入通信详情观察 ACK 连接状态；进入姿态详情查看校准状态。传感器就绪不代表无线一定在线。

## 菜单操作

| 所在页面 | 按键 | 动作 |
|---|---|---|
| 主目录 / 详情 | KEY1、KEY2 | 上/下选择或切换四类页面 |
| 主目录 | 短按 KEY3 | 进入选中详情 |
| 任意详情 | KEY4 | 返回目录 |
| 摇杆详情 | 短按 KEY3 | 校准机械中心 |
| 按键/开关详情 | 短按 KEY3 | 清事件显示计数 |
| 通信详情 | 短按 KEY3 | 清显示计数，不重置链路序号 |
| 姿态详情 | 长按 KEY3 至 2 秒 | 重新开始 IMU 校准 |

按键使用 20 ms 消抖、2 秒长按和 300 ms 双击窗口。PRESS/RELEASE 是物理边沿，LONG/DOUBLE 是附加手势；双击仍包含两次 PRESS，没有单独的延迟 SINGLE_CLICK 事件。三击不会生成重叠双击。

拨码显示引脚高低电平：高为 1，接地为 0；变化稳定 60 ms 后发布。

## 串口与输出模式

两端 USART2 均为 115200、8N1；无线数据走独立 USART1。

| 端 | 默认输出 | 操作方式 |
|---|---|---|
| 发送端 | 文本采样日志和 KEY 事件 | 约 10 Hz 采样日志，事件日志优先 |
| 接收端 | JustFloat | 使用 JustFloat 解码读取 14 通道 |
| 接收端文本模式 | `R` 遥测与 `STAT` 统计 | 向接收端 USART2 发送 ASCII `T`（小写也可） |
| 切回 JustFloat | 二进制 60 字节帧 | 发送 ASCII `F`（小写也可） |

按键事件使用 31 项有效容量队列，溢出累计记录在 KEY 日志的 lost 字段。查看波形时不要混用文本解码；使用 VOFA+ 时选择 JustFloat，观察通道 0/1（摇杆）或 6/7/8（姿态）。物理串口与 VOFA+ 连接仍待实际验证。

## JustFloat 通道

接收端发送 14 个小端 IEEE754 float，后接 4 字节尾标，共 60 字节。通道含义如下：

| JustFloat 通道（从 0 开始） | 含义 |
|---|---|
| 0、1 | 摇杆 X/Y，-1000…1000 |
| 2、3 | X/Y 电压，V |
| 4、5 | 按键低四位、开关低两位掩码 |
| 6、7、8 | Pitch、Roll、Yaw，度；Yaw 是相对偏航 |
| 9 | 去重后的有效新包 Hz |
| 10 | 序号缺口推算的最终丢包率，% |
| 11 | 通过协议及载荷检查的到包 Hz，含重复/过期包 |
| 12 | 故障标志：bit0 IMU、bit1 校准中、bit2 ADC、bit3 OLED |
| 13 | 连接状态：1 在线、0 等待/离线 |

在线 JustFloat 只为新遥测发送一帧，统计随下一新帧更新，避免人为抬高转发频率。等待/离线时每秒可输出状态快照（通道 13 为 0，不能算有效遥测）。文本中 `R` 是新遥测，`STAT` 为每秒统计：unique/lost/duplicate 是累计数量，Hz10/loss10 除以 10 还原 Hz/%。

## 读懂日志

| 输出 | 如何解释 |
|---|---|
| 手柄 `S x=… y=… mv=…` | 映射值与毫伏；`a/g` 为原始加速度/角速度计数 |
| 手柄 `raw10=… out10=…` | 原始倾角和滤波输出均为角度 ×10；可用于后续实测对比 |
| 手柄 `KEY t=… K… PRESS/RELEASE/LONG/DOUBLE lost=…` | 事件发生 tick、按键编号、类型及日志队列溢出累计数 |
| 接收端 `R id=… deg10=… hz10=… loss10=…` | 新遥测；角度、Hz、百分比的整数值除以 10 还原 |
| 接收端 `STAT unique=… lost=… duplicate=…` | 累计新包/推算丢包/重复包，不是本秒计数；Hz10 才对应统计窗口频率 |
| 接收端文本 `link` | 0=等待同步、1=在线、2=离线；与 JustFloat 的 0/1 布尔状态不同 |
| 接收端 `flags` / OLED `ERR` | 故障位组合，不是错误数量，按通道 12 的位定义读取 |

## 常见现象

| 现象 | 含义与检查方向 |
|---|---|
| 上电 CAL 持续显示 | 尚未收集到 100 个连续合格样本；保持静止并检查 IMU 状态 |
| 通信页 ACK link:WAIT | 未收到过有效 ACK 或 ACK 已超时；检查两方向串口与接收端 |
| 接收屏 LOST，摇杆值仍显示 | 显示的是最后快照，不能继续当作新控制输入 |
| loss=0 但曾断链 | 离线重新同步后无法精确重建缺失帧数；结合 link/expired 判断 |
| 持续静止时 Yaw 缓慢变化 | 六轴相对偏航可能漂移；不是绝对航向测量 |
| 串口助手出现乱码 | 先确认 115200 8N1，并检查是否把默认 JustFloat 当成文本；发送 T 可切文本 |
| 转发计数小于接收新包数 | 检查 PC 发送忙导致的 pc_drop；它与无线丢包分开统计 |

参数修改位置和默认值见[硬件映射与配置](hardware-configuration.md)；具体帧格式和丢包定义见[通信协议](protocol.md)。
