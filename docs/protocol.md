## 遥测帧：23 字节

所有多字节字段显式小端编码，不依赖结构体内存布局。

| 偏移 | 字节数 | 含义 |
|---|---:|---|
| 0–1 | 2 | AA 55 |
| 2 | 1 | seq，0…255 回绕；同一重传保持不变 |
| 3 | 1 | payload 长度 10 hex（16） |
| 4 | 1 | cmd = 01 |
| 5–6、7–8 | 各 2 | int16 X/Y 映射值，-1000…1000；历史变量名 joy_x_raw/joy_y_raw |
| 9–10、11–12 | 各 2 | uint16 X/Y 毫伏，0…3300 |
| 13 | 1 | bit0…3 按键按下掩码；bit4 IMU 故障，bit5 正在校准，bit6 ADC 故障，bit7 OLED 故障 |
| 14 | 1 | bit0/1 SW1/SW2 引脚稳态电平，高 1、低 0，其余 0 |
| 15–16、17–18、19–20 | 各 2 | int16 Pitch/Roll/Yaw ×10，即单位 0.1°；历史后缀 cd 不表示 0.01° |
| 21 | 1 | sum(bytes[2:21]) & FF，不包括帧头/自身/帧尾 |
| 22 | 1 | 0D |

Pitch 正常解算范围 -90…90°、Roll -180…180°，Yaw 为 0…360° 的相对航向（取整可能到 3600）。接收端校验字段范围，错误帧不更新遥测、不 ACK。

测试向量（seq=254，X=-1000、Y=1000、电压=3300/0、key=15、sw=3、角度=-1800/1800/3600；用于编码边界，不代表正常姿态）：

```text
AA 55 FE 10 01 18 FC E8 03 E4 0C 00 00 0F 03 F8 F8 08 07 10 0E 2D 0D
```

累加和保留已有 23 字节布局且计算简单，但不能检出所有多字节抵消错误；不是强 CRC 检错或安全认证。

## ACK 帧：9 字节

```text
AA 55 seq 02 80 token_lo token_hi sum 0D
```

sum 覆盖 seq、02、80、token_lo、token_hi。token 是原遥测全部 23 字节的 CRC16-CCITT-FALSE（poly=1021 hex、init=FFFF、非反射、xorout=0）；`123456789` 校验结果 29B1。ACK 需同时匹配待确认 seq 与 token，避免大部分旧 ACK/内容不同但序号相同的误确认。16 位 token 不提供唯一会话标识或抗攻击保证。

## 发送端状态与接收规则

1. 初始化后 1500 ms 静默期，仅禁止遥测发送；采集、校准、显示照常工作。接收端超过 1000 ms 无可接受新包/重复包即离线并丢弃旧序号基准，随后第一帧建立新基准。该策略可处理测试中的发送端独立重启；具体无线缓存延迟需实测，不能保证无限延迟旧包下的会话识别。
2. 每 20 ms 采集最新数据，仅在没有未确认帧时尝试提交。UART 忙时不增加 seq。发送成功后等待 ACK，80 ms 未确认则重发同一字节快照，最多 2 次；首次发送后到 240 ms，在主循环下一次执行超时检查时结束等待；任务先处理 ACK，再执行超时轮询。下一次采样发送最新值，不积压所有历史样本。
3. 正确 ACK 结束等待并使 seq 加一；最终超时也使 seq 加一。没有待确认帧、序号或 token 不匹配的 ACK 忽略。重复遥测回复 ACK，但不重复更新控制数据、不重复转发 PC。
4. 接收端 seq 差采用 uint8 模 256 运算：1…127 为前进，其中 diff-1 是推算的最终缺包；diff=0 且 token 一致为重复；相同序号不同 token 或 diff≥128 为过期数据。长时间离线后重新同步，不沿旧序号计算缺口。
5. 解析器检查长度/功能码组合（遥测 16/01、ACK 2/80）、和校验、帧尾。校验失败从下一字节滑动重找 AA55，保留潜在重叠头；半帧跨调用保留，消费字节时间间隔超过 100 ms 清旧半帧。单次无法保证一个字节内重新同步，但工作量有固定 23 字节界限。UART 接收溢出/错误后清半帧与接收缓冲。

## 统计口径与 PC

以约 1000 ms 窗口更新，若主循环延迟，用实际 elapsed_ms：

- uniqueHz = 去重后新包数 × 1000 / elapsed_ms。
- wireHz = 通过协议和载荷检查的到包数（含重复/过期）× 1000 / elapsed_ms。
- loss% = 推算缺包 /（新包 + 推算缺包）×100。重传补回的包不计最终丢失。
- 离线时 Hz=0，保留最后遥测并输出 link=0。完全断链期间丢了多少帧无法从本协议精确重建；loss=0 也不能说明从未断链，须结合 link、发送端 expired、重复计数看。

USART1 115200 8N1，50 Hz ×（23+9）×10 = 16000 bit/s（未含空口开销），实际吞吐还取决于无线转发时延。停止等待无法在 ACK RTT≥20 ms 时保证 50 Hz。

PC USART2 默认 14 个 LE IEEE754 float（56 B）+ `00 00 80 7F`（4 B），映射见[操作与上位机](user-guide.md)。每个新遥测最多转发一次；在线统计搭载下一帧，不另发重复波形采样。离线/等待状态快照 link=0 不计有效采样。UART 忙时丢弃本次转发并累计 pc_drop，保证采集和无线处理继续运行。`T`/`F` 切换文本/JustFloat，文本 `STAT` 按秒报告统计，`R` 表示新遥测。

修改该文件对应协议时，应同步双方 Service、接收 App、PC 通道说明及 tests。
